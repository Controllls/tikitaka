# 티키타카 현재 기능명세

기준일: 2026-11-11   프로젝트: 우리집 시트콤   상태: 사용자 확정 범위와 현재 UI를 기준으로 한 기획·디자인 명세. 앱 구현 완료나 실차 검증 통과를 뜻하지 않는다.

티키타카는 차 안의 대화를 녹음하고, 고정 캐릭터와 자막이 등장하는 영상으로 남기는 서비스다. 내 프로필은 하나이며, 보관함은 완성 영상과 제작 작업을 다루는 **에피소드**, 저장한 원음을 다루는 **녹음** 두 탭으로 구분한다.

2026-11-10 변경에 따라 녹음 목록에서 **제작 완료 녹음은** **`녹음 듣기`****, 아직 제작을 시작하지 않은 녹음은** **`동영상 생성하기`**를 주동작으로 제공한다. 기존의 모든 녹음 행을 `녹음 듣기`로 통일한 규칙보다 이 기준을 우선한다.

**2026-11-11 최신 기본 흐름:** 녹음 시작 → 직접 종료 또는 시동 OFF 정상 종료 → 원음 저장 성공 확인 → 자동 제작 → 에피소드 보관함. 시작 전에 `이번에는 녹음만 보관`을 선택한 세션은 저장 후 녹음 보관함으로 이동한다. 시동 OFF 신호만으로 저장 성공을 판정하지 않으며, 즉시 제작할 수 없으면 제작 대기를 보존한다. 앱 재실행 시 미완료 세션의 실제 저장 상태를 확인한다. I-01은 재선택 없는 저장 결과 안내이고 저장 실패·무음·불완전 복구는 자동 제작하지 않는다.

## 1 확정 범위와 제외 범위

| 구분 | 현재 기준 |
|---|---|
| 주요 메뉴 | 차량의 사이드바 제공 화면은 `홈 / 보관함 / 캐릭터`와 하단 `설정`으로 통일한다. 캐릭터는 독립 탭에서 진입하며 설정의 `내 캐릭터` 중복 항목은 제거한다 |
| 내 프로필 | 프로필 하나. 최초 이름·캐릭터 설정 유지. 이름 저장은 설정 복귀, 일반 캐릭터 확정은 캐릭터 탭 유지. 모두 다음 영상 적용 토스트 제공 |
| 캐릭터 | 기본·메인 캐릭터는 청록(04). 최초 진입에 적용하고 이후에는 사용자가 선택한 캐릭터를 유지. 고정 8종과 선택 관련 3D 에셋 사용 |
| 녹음 | 동승자 안내·동의 확인, 시작, 진행 상태, 일시정지, 직접 재개, 정차 후 종료·저장 |
| 영상 제작 | 기본은 정상 원음 저장 성공 후 자동 제작·에피소드 탭 이동. 시작 전 `이번에는 녹음만 보관`을 선택한 세션만 저장 후 녹음 탭으로 이동. 보관한 미제작 원음의 나중 제작과 기존 작업 복구는 유지 |
| 감상 | 원음 재생과 완성 영상 감상 분리. 차량 영상 감상은 정차 상태에서 제공 |
| 휴대폰 | 설정에서 선택적으로 연결. 초기 설정·녹음·영상 제작에 필수 선행하지 않는 추가 감상·공유 기능 |
| 제외 | 운전자 선택·추가와 다른 운전자 화면 `C-02 / D-03 / D-04 / D-05` 계열 |
| 제외 | 헤어·색상·의상·안경 등 외형 꾸미기, 동승자 목소리 기억·인물 관리, 대사·발화자 수동 수정 |

**최신 결정: 운전자 내 목소리 확인(FN-15)을 MVP에 다시 포함한다.** 최초 이름·캐릭터 입력 완료 뒤 선택적으로 확인하고 나중에 진행할 수 있다. 설정에서도 미등록/확인됨을 표시하고 재등록할 수 있다. 성공한 확인만 단일 내 프로필의 음성 등록에 저장한다. 실제 녹음에서 등록 목소리와 운전자가 확인되면 저장한 내 캐릭터를 연결하며, 미등록·매칭 불확실 상태에서도 일반 화자 자동 배정으로 녹음·제작을 계속한다. 운전자를 임의 추정하지 않는다.

설정에서 이름 변경을 저장하면 설정 화면으로 돌아가고, 독립 캐릭터 탭에서 선택을 확정하면 해당 캐릭터 화면에 머문다. 두 경우 모두 `다음 영상부터 적용돼요` 토스트를 2.4초 표시한다. 적용 대상은 이후 제작할 영상이며 이미 완성된 영상의 이름·캐릭터 배정은 바꾸지 않는다. 최초 이름 입력 중 캐릭터 확정은 이름 입력 화면으로 돌아가며, 온보딩 완료 후 홈으로 진입하는 흐름은 유지한다.

최초 진입에서 선택 이력이 없을 때만 청록 캐릭터(04)를 기본으로 표시한다. 사용자가 다른 캐릭터를 선택·저장했다면 재진입·이름 입력·미리보기에서도 그 선택을 유지한다. `캐릭터 01` 같은 미리보기 라벨은 숨기되 `이 캐릭터로 선택` 확정 버튼은 계속 제공한다. 여기의 04는 에셋·화면 연결용 식별자이며 선택 UI의 이름표가 아니다.

캐릭터 선택은 8종을 순환하는 회전형 캐러셀이다. 선택 후보와 좌우 3개씩 총 7개를 보여주며, 반대편 1개는 전환할 때 양끝에서 순환 등장한다. 선택 후보와 큰 미리보기는 같은 중앙축을 사용한다. 현재 1700 × 1184 기준 일반 캐릭터 탭의 8상태는 사이드바를 제외한 콘텐츠 중앙 x=915.5, 최초 이름 설정의 8상태는 전폭 중앙 x=850을 사용한다. 좌우 버튼은 한 칸 전후로 이동하며 8↔1로 순환한다. 보이는 후보를 눌러 직접 탐색할 수도 있다. 탐색은 임시 상태이며 `이 캐릭터로 선택` 확정 버튼을 눌러야 저장한다. 확정하지 않고 뒤로 나가면 기존 저장 선택을 유지한다.

Figma에서 방향 화살표는 한 칸을 약 0.35초 SMART\_ANIMATE로 이동한다. 먼 후보 직접 선택은 중앙을 가로지르는 직선 이동 대신 인접 상태를 1\~3칸 순차 회전하며 각 칸은 약 0.24초다. 기존 선택 화면 16개와 남은 칸 수·방향 변수, 조건부 지연 연결로 목적 후보에서 멈춘다. 브라우저에서 04→07→04·04→01 순차 전환과 01→08→01 경계 순환을 확인했다. 실제 앱 회전·감속·연속 입력 검증은 별도다. 보관함의 미제작 녹음 `동영상 생성하기`·완료 녹음 `녹음 듣기` 및 기존 작업 재개·재시도 규칙은 유지한다.

Figma 프로토타입은 `UX/savedCharacterIndex`(기본값 4)를 확정 버튼에서만 갱신한다. 전역 캐릭터 탭의 모든 진입은 저장값 1\~8에 따라 해당 선택 화면을 연다. 취소·화살표·후보 탐색은 저장값을 바꾸지 않는다. 최초 설정과 일반 선택의 확정 16개·재진입 14개·조건 112개는 전역 메뉴 통일 전 검수 이력이며 현재 진입 수를 뜻하지 않는다. 프로토타입 세션 유지와 앱 재시작·기기 영속 저장 검증을 구분한다.

## 1.1 홈 원본을 기준으로 한 공통 디자인

차량 앱은 **넓은 1700 × 1184px / 좁은 840 × 1184px** 두 레이아웃을 제공한다. 현재·보조 차량112개 화면 상태와 저장 안내 오버레이를 양쪽에 대응시켰으며, 기능·변수·상태·이동·복귀 정책은 같다. 2026-11-11 사용자 승인으로 이전 좁은 대표 홈1장 승인 대기·추가 변형 금지 조건을 해제했다. 넓은 최종 홈을 공통 시각 기준으로 사용하고 좁은 화면은 콘텐츠를 재배치한다. 넓은 홈은 사이드바130px·히어로980px·최근 에피소드590px, 일반 화면은 사이드바130px+구분선1px+콘텐츠1569px이다. 좁은 일반 화면은 사이드바130px+구분선1px+콘텐츠709px, 콘텐츠 좌우 여백32px를 사용한다. 넓은 일반/최초 중앙축은 x=915.5/850, 좁은 일반/최초 중앙축은 x=485.5/420이다. 이전1682 × 1210·841 × 1210은 과거 규격으로 보존한다. 이는 Figma 설계·배치 기준이며 실제 앱의 화면비 전환·상태 복원·실차 검증 완료를 뜻하지 않는다.

사람이 디자인한 최신 홈을 시각 기준 원본으로 보존하고 적용본은 글자·버튼·목록·아이콘을 편집 가능한 컴포넌트로 구성한다. 넓은 홈의 최신 원본은 `codex-clipboard-eed8d6dd-8b76-45d9-9be7-6049c6519926.png`이며, 1700 × 1184px로 환산한 픽셀 배치에 맞춘다. 넓은 홈의 외곽은 모서리 반경 40px, 테두리 1px·#C9CACD를 사용한다. 사이드바·캐릭터 면·오른쪽 에피소드 면과 원본 로고·캐릭터·조명·질감, 캐릭터와 녹음 버튼의 비례·여백을 유지한다. 원본의 작은 행별 위치 차이도 보존하며 임의로 균등 간격으로 재배치하지 않는다.

최종 홈 에셋 기준은 손인사 청록의 아주 옅은 크림빛 웜화이트 얼굴, 매트한 3D 말풍선과 은은한 좌상단 조명이다. 문구는 `오늘은 어떤 이야기를 들려줄래?`이며 편집형 텍스트를 유지한다. 넓은 홈 전용 히어로 마스터 `965:1859`는 말풍선 545.23 × 146.72px·Jua Regular 34.8px·외곽선 없음, 표면 3색 #FFFFFF / #FBFAF8 / #EFEDE9, 검정 16%·y=8px·blur=14px 그림자를 사용한다. 캐릭터 접지 그림자는 편집 가능한 방사형 그라데이션 3개로 원본에 맞춘다. 좁은 홈은 기존 승인 대표 홈의 히어로 배치와 에셋을 이어 사용하며, 넓은 전용 히어로 규격을 강제로 축소하지 않는다. 정면 고정 8종 선택 에셋은 이 홈 손인사 에셋과 별개다.

최근 에피소드 패널은 첨부 원본의 비례·행 간격을 기본값으로 사용한다. **한 줄 헤더·에피소드 텍스트 우측 정렬·주차 안내 문구 제거는 840 × 1184px 좁은 대표 홈에만 적용한다.** 넓은 홈의 `전체 보기`는 제목 아래 높이 41.04px의 별도 줄에서 우측 정렬하고, 에피소드 번호·제목은 좌측 정렬한다. 넓은 홈의 행은 약 240px 간격을 기준으로 원본에서 실측한 행별 미세 위치를 보존한다. 썸네일 우하단 재생 버튼과 아래 방향 그림자(y=3px, blur=6px, 18%)는 유지한다. 앱 폰트는 Asta Sans를 유지하고 말풍선에만 주아체를 쓴다. SOURCE 원본·과거 비교 시안은 이력으로 보존한다.

캐릭터 선택·프로필·홈 캐릭터는 3D 에셋이며, 완성 에피소드를 나타내는 썸네일은 사용자가 제공한 2D 10종(16:9)을 사용한다. 이 두 용도는 별개다. 2D 썸네일 10종은 디자인 시스템에 원본과 사용 규칙을 보관하고, 같은 에피소드는 동일한 썸네일을 사용하는 것이 원칙이다. 홈 EP.04는 첨부 원본의 토끼·병아리·청록·곰 장면을 사용하며 이번 좁은 홈에도 같은 홈 에셋을 반영한다. 2026-11-10 넓은 홈만 원본 썸네일로 수정했던 작업 범위는 과거 이력이다. 이 예외는 기능이나 에피소드 데이터를 새로 추가하는 것이 아니며, 서로 다른 데이터 예시만으로 독립 화면을 반복 추가하지 않는다.

- 전역 사이드바는 홈·보관함·캐릭터와 하단 설정을 제공한다. 캐릭터 메뉴 아이콘은 사용자가 직접 디자인한 홈의 사람형 선형 아이콘을 사용한다. 전역 아이콘은 32 × 32px 슬롯, 선 굵기 2.4px, 색상 #4D4D4D를 기본으로 한다. 넓은·좁은 차량 화면의 공통 사이드바는 홈 메뉴 밑선을 표시하지 않고 하단 설정은 라벨 없는 아이콘으로 표시한다. 설정 아이콘은32 × 32px 슬롯 내부 y=8의 상단 정렬을 사용한다. 현재 탭의 글자 굵기는 기존 상태를 유지하고, 주행·녹음 중 비활성/숨김 메뉴와 기능 연결은 보존한다. 설정에 내 캐릭터를 중복 배치하지 않는다.
- 넓은 홈의 `최근 에피소드` 제목은 Asta Sans 34/44, 개수는 14/20을 사용한다. 제목·개수 간격은 17px, 개수 프레임 상단은 헤더 안에서 17px로 원본 실측에 맞춘다. `전체 보기`는 14/20으로 높이 41.04px의 별도 줄에서 우측 정렬한다. 에피소드 행은 메타 16/20과 제목 22/22를 좌측 정렬하고, 원본의 각 행별 위치를 유지한다. 하단 주차 안내 문구는 14/20으로 표시하며 영상 재생의 주차 조건을 유지한다. 내부 페이지 제목은 Asta Sans SemiBold 36/48, 본문 Regular 24/32, CTA·목록/카드 제목 Medium 24/32, 메타 Regular 18/24, 보조 문구 16/24를 기준으로 한다.

## 1.2 운전자 목소리 확인 · 최신 MVP 흐름

최초 이름·캐릭터 입력 완료 뒤 MISSING-VOICE 안내에서 확인하거나 `나중에 하기`로 홈 H-01E에 진입한다. 설정 S-01의 `내 목소리 확인`은 미등록/확인됨 상태를 표시하고 같은 4화면으로 확인·재등록한다. 별도 운전자 선택·추가 기능은 만들지 않는다.

- 공유 화면: MISSING-VOICE 안내 → VOICE-02 확인용 녹음 → VOICE-03 성공 / VOICE-04 실패·재시도.
- 진입 출처를 유지한다. 최초 진입 완료·나중에는 H-01E, 설정 진입 완료·취소는 S-01로 돌아간다.
- 성공한 확인만 등록한다. 재등록도 새 성공 때만 기존 참조를 대체하고 실패·취소·이탈은 기존 등록을 유지한다.
- 등록 정보는 단일 내 프로필에 귀속한다. 이름·캐릭터 변경만으로 등록을 초기화하거나 재등록을 요구하지 않는다.
- 등록은 실제 대화에서 내 목소리를 찾아 선택 캐릭터와 연결하기 위한 참조다. 실제 매칭 품질·불확실 판정은 개발 검증 대상이며, 미등록·불확실이어도 녹음·제작을 막지 않는다.
- 확인은 주차 중에만 진행한다. 주행 전환 시 확인을 중단하고 기존 음성 등록을 유지한다. 미완료 시도는 등록 성공으로 저장하지 않는다.
- 저장 위치·보존 기간·동의 및 삭제 정책은 아직 미정이다. 성공 화면만으로 실제 음성 저장·인식 검증 완료로 보지 않는다.

Figma의 `UX/voice/entryOrigin`은 최초/설정 복귀를, `registered`·`registrationStatus`는 등록 표시를 관리한다. `demoResult`·`isParked`는 인식 결과와 주차 조건을 시연하기 위한 변수이며 실제 인식·차량 이벤트가 아니다. VOICE-02의 `읽기 완료` 뒤 성공 결과 분기에서만 등록 상태를 갱신한다. 실패·취소·주행 분기는 기존 값을 유지하며 실제 음성 참조 저장과 차량 이벤트 연동은 개발 검증 대상이다.

## 1.3 동일 기능 지도 · 넓은/좁은 레이아웃

### 3.1 자동 제작 기본값과 사전 선택

새 녹음 준비에서 `이번에는 녹음만 보관`을 선택하지 않으면 정상 저장 성공 후 자동으로 제작한다. 녹음 시작 뒤에는 이번 세션의 선택을 바꾸지 않으며 I-01에서 제작 여부를 다시 묻지 않는다. 이 선택은 이번 녹음에만 적용하며, 종료 후 다음 새 녹음 준비(R-00)를 열면 체크가 해제되어 기본 자동 제작으로 시작한다. 종료된 세션의 선택값은 저장 재시도·복구·제작 대기 처리를 위해 유지한다.

자동 제작 조건은 `recordOnly=false` AND `recordingResult=saved` AND `autoProductionEligible=true` AND 같은 원본 녹음의 기존 제작 작업 없음이다. `autoProductionEligible`은 기본false이며 실제 저장 검증 통과 이벤트에서만true가 된다. 저장 대기·판정 미상은 통과시키지 않는다. 원음 저장 실패·무음·강제 종료 후 불완전 복구는 자동 제작에서 제외한다. 정상 원음 저장 뒤 네트워크가 끊긴 상황은 저장 실패와 구분하여 기존 제작 작업의 G-02 대기·재개 흐름으로 처리한다.

새 R-00 세션에서만 recordOnly=false·recordingResult=pending·autoProductionEligible=false·recordJobCreated=false를 초기화한다. M-01·권한 왕복, 일시정지·재개, 화면비 전환과 기존 세션 복귀는 값을 유지한다. 프로토타입의 `UX/demo/recordingResult` 기본saved는 화면 분기 시연을 위한 모의 값이고 실제 앱 저장 검증이 아니다. 저장 결과 판정과 작업 접수는 앱 책임이며 I-01 진입·CTA·1.5초 자동 이동은 새로운 제작을 반복 접수하는 트리거가 아니다. G-00을 다시 여는 것도 새 작업 접수로 보지 않는다.

시동 OFF의 정상 종료 처리, I-03의 기존 사이드바 이탈, 재실행 시 실제 저장 상태별 복구 분기는 2026-11-11 사용자 확정이다. 시동 신호/API 권한·마감 가능 시간, 영속 임시 음원의 저장 매체·보존 기간, 파일 검증·복구 구현은 별도 기술 검증 대상이다. 기존 주행 중 수동 종료 제어와 Gleo 분기 통합은 이번 결정으로 변경하지 않는다. Figma 설계와 실제 저장·생성·실차 검증은 구분한다.

### 3.2 시동 OFF·재실행·저장 실패 처리

- **정상 종료:** 사용자의 직접 종료와 시동 OFF를 같은 정상 종료 계기로 취급한다. 녹음 파일 마감 → 저장 성공·사용 가능 검증 순서를 지킨다. 시동 OFF 수신이나 화면 이동만으로 `saved`/제작 가능을 확정하지 않는다.
- **제작 대기:** 정상 저장본은 세션의 `recordOnly` 선택을 유지한다. 자동 제작 세션에서 전원·네트워크 때문에 접수하지 못하면 원음 ID와 제작 대기를 영속 보존하고 다음 실행·연결에서 접수한다. 기존 작업 ID가 있으면 그 작업을 복원하며 같은 원음의 두 번째 작업을 만들지 않는다.
- **I-03 이탈:** 본문에 별도 `홈으로` 버튼을 추가하지 않고 기존 사이드바의 홈 등으로 나간다. `다시 저장하기`는 원음 저장 결과를 다시 검증한다. 저장 실패 상태에서 제작 화면으로 곧바로 진행하지 않는다.
- **실패 원음 보존:** 영속 임시 파일이 실제로 남아 있는 경우에만 이탈 후 보존을 안내하고 기존 녹음 탭에 `저장 확인 필요`로 표시한다. 새 복구 관리 메뉴는 만들지 않는다. 파일이 없으면 복구 불가·다시 녹음을 안내한다. 메모리에만 있는 음원을 기기에 보관됐다고 표시하지 않는다.
- **재실행:** 시작/홈 진입에서 미완료 세션을 확인한다. 정상 저장본은 세션 선택과 기존 제작 작업을 복원한다. 부분 원음만 복구되고 그 저장이 확인된 경우에만 I-04를 표시하고 자동 제작에서 제외한다. 복구할 음원이 없으면 복구 불가를 안내한다. 미완료 세션이 없으면 일반 홈으로 진입한다. 크래시·전원 차단만으로 모든 녹음을 I-04로 분류하지 않는다.

| 재실행 확인 결과 | 처리 |
|---|---|
| 미완료 세션 없음 | 일반 홈 진입 |
| 정상 원음 저장 완료·녹음만 보관 | 녹음 보관함 복원, 자동 제작 없음 |
| 정상 원음 저장 완료·제작 작업 있음 | 기존 작업 복원·재개, 중복 접수 금지 |
| 정상 원음 저장 완료·자동 제작 미접수 | 영속 제작 대기를 읽어 접수·재개, 연결 대기는 기존 G-02 맥락 사용 |
| 부분 원음 복구·저장 확인 | I-04 → 녹음 보관함, 자동 제작 제외 |
| 영속 임시 원음만 남음·저장 미확인 | I-03/녹음 탭 `저장 확인 필요` → 저장 재시도 |
| 미완료 세션은 있으나 복구할 원음 없음 | I-05 복구 불가 안내·다시 녹음, 제작 금지 |

녹음별 화자를 구분한다. 등록한 목소리와 실제 녹음의 운전자가 확인되면 단일 내 프로필에 저장한 캐릭터를 연결하고, 동승자는 나머지 고정 캐릭터를 자동 배정한다. 같은 녹음 안에서 같은 화자는 같은 캐릭터를 일관되게 사용한다. 미등록·매칭 불확실이면 운전자·첫 화자를 임의 지정하지 않고 일반 화자 자동 배정으로 계속한다. 서로 다른 화자를 캐릭터가 같다는 이유로 합치지 않고, 동승자를 다음 녹음의 실제 사람으로 영구 기억하지 않는다. 등록 성공 UI가 실제 녹음에서의 운전자 매칭 정확도를 증명하지는 않는다.

완성 영상은 제작 당시 배정을 유지한다. 이름·캐릭터 변경은 다음 제작 영상부터 적용되며 과거 영상에 자동으로 소급되지 않는다. 또한, 재생·내보내기마다 음성을 다시 분석하거나 캐릭터를 다시 추첨하지 않는다. 최대 화자 수와 캐릭터 8종을 초과하는 상황의 처리는 개발 검증 후 확정한다.

## 7 개인정보와 삭제의 확정 수준

- 동승자 안내·동의 확인 M-01은 첫 녹음 때 제공하고, 다시 보기는 설정의 녹음과 개인정보 S-02에서 제공한다. 녹음 일시정지와 공유 전 목소리 포함 안내는 유지한다.
- 공유 미리보기에서 사용자가 공유를 선택해야 OS 공유 단계로 이동한다. 미리보기 열기만으로 외부 전송하지 않는다.
- 원본 녹음, 제작 작업, 완성 영상을 구분한다. 휴대폰 보관함의 개별 에피소드 삭제는 유지한다. 설정 일괄 기록 삭제를 MVP에서 제외하는 안은 권고이며 사용자 확정 전이다. 개별 삭제가 원음·연결 영상·진행 작업에 미치는 범위는 아직 확정되지 않았다.
- 보존 기간, 삭제 복구 가능 기간, 저장 위치와 전송 경로, 접근 권한·인증·암호화의 구체 구현, 동의 기록의 보관 방식은 확정·검증이 필요하다.
- 복수 영상 제작과 완성 영상 재생성 정책은 미정이다. 현재 중복 생성 차단 UI만으로 장기 정책을 확정하지 않는다.
- `S-03`은 일괄 삭제 제외 제안에 따른 권고 보류다. 휴대폰 보관함의 개별 삭제 확인·결과 UI는 유지하지만 실제 데이터 삭제나 연결 자료 전체의 삭제 완료를 증명하지 않는다.

### 별도 기술 검증 · 운전자 음성 등록과 실제 매칭

음성 등록 품질·성공 판정, 실제 녹음의 운전자 매칭과 불확실 판정 기준을 검증한다. 미등록·매칭 불확실 시 일반 화자 자동 배정, 성공한 재등록만 대체, 실패·취소 시 기존 등록 보존, 이름·캐릭터 변경 후 등록 유지가 통과 기준이다. 확인용 음성의 저장 위치·보존 기간·동의 및 삭제 처리는 저장·개인정보 정책에서 정해야 한다.

화자 분리의 반복 오류는 해결 확인 전이다. 실제 발화자·분리 결과·자막·캐릭터 연결을 대조하여 정확도와 한계를 기록하고, 차량 주행 상태·권한·백그라운드 녹음·영속 저장은 실제 기기에서 별도로 검증한다.

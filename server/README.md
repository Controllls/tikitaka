Android 앱과 별도로 실행하는 Python/FastAPI 서버입니다. 설치별 자동 인증, 녹음 업로드, 자동 하이라이트 추출, 화자·웃음·한국어 자막·목소리 특징 분석을 담당합니다. Android SDK, Gradle, 에뮬레이터 없이 실행할 수 있습니다. 현재 앱의 녹음·분석·하이라이트 선택·영상 합성은 `../app/`에서 독립적으로 처리합니다. 아래 서버 연동 설명은 PC 실험 및 이전 구현용입니다.

## 영상 제작 실험 웹페이지 — 소스·모델 선택부터 MP4까지

**http://127.0.0.1:8770/** 에서 **음성 입력 → 6개 AI 분석 → 배경·차량·캐릭터 파츠 합성 → MP4 재생·다운로드**까지 시험합니다. 앱을 실행할 필요가 없습니다. 앱 기본 소스를 제공하며 사용자 소스로 바꿀 수 있습니다. 같은 음성으로 모델 조합을 바꿔 실행하고 **비교** 탭에서 영상·처리 시간·분석 출력을 확인합니다.

**웹 기본은 ‘캐릭터별 구간 분석’입니다.** 녹음 전체에서 Nemotron 화자 기준과 ECAPA 목소리 기준을 확보한 뒤, 최대 8초 구간(앞뒤 0.5초 문맥)을 독립 분석합니다. 말하기·웃음·해당 음성의 음량을 동시에 보관하고 캐릭터별로 재생합니다. ‘캐릭터·구간’ 탭에서 원본/분리 음성 듣기, 화자 수정, 한 구간 재분석, 미확정·실패 필터를 사용할 수 있습니다. 수정은 새 기록으로 남고 이전 기록은 유지됩니다. 재분석은 동일 시간의 분리 음성을 함께 처리하며 직접 지정한 화자를 보존합니다. 대사가 변경되면 주제·하이라이트도 다시 계산합니다. 영상 재제작에는 수정한 기록을 사용합니다.

구간 겹침 또는 말+웃음 후보에는 [SpeechBrain SepFormer WHAMR16k](https://huggingface.co/speechbrain/sepformer-whamr16k)를 적용합니다(revision `21a5b500c6f52fddc387c5d9e5fb13ffd6f039c5`). 두 음원 모델이며 세 명 이상 겹침에는 분리 한계가 있습니다. 분리 출력 순서를 사람 번호로 간주하지 않고, 일반 발화에서 얻은 목소리 기준과 대조합니다. 근거가 부족한 구간은 아래 화자 재검토 설정에 따라 처리합니다. 한국어 차량 환경·웃음 정확도가 보장되는 모델은 아니므로 실제 파일을 듣고 검토해야 합니다. `[웃음]` 자막은 옵션으로 켜고 끕니다. 끝까지 미확정인 웃음도 아래 추정 배정 정책에 따라 캐릭터 동작으로 연결합니다.

**화자 매칭 재검토:** 웹 기본 선택은 **임시 배정 + Claude 문맥 검토**입니다. ‘Claude API 키 연결’에 Anthropic 키를 넣고 계정에서 조회한 모델을 선택합니다(모델 ID 직접 입력도 가능). 서버 `ANTHROPIC_API_KEY` 또는 `server/.env` 설정도 지원합니다. API 키는 세션 메모리와 작업 표준 입력으로만 전달하며 결과·설정 파일·명령행에 기록하지 않습니다. 기존 OpenAI 주제/STT 선택과 별개인 화자 검토 기능입니다. 키 없이 시험하려면 **음성 근거로 임시 배정**을 선택합니다. 기존 API 요청은 호환성을 위해 로컬 임시 배정이 기본입니다.

**웃음 감도:** ‘캐릭터별 구간 분석’과 ‘모델별 실험’에서 음성 처리 기준 아래의 감도 슬라이더·빠른 선택·직접 입력(0.001~1)을 사용합니다. 낮은 기준값이 높은 감도이며 기본 0.1은 이전 판정을 유지합니다. 캐릭터 구간 모드는 점수의 절대 판정 기준과 후보 구간 기준을 함께 조절하고 원래 모델 점수·소음 대비 검사·최소 길이는 유지합니다. 설정은 웃음 자막·캐릭터 표정·하이라이트 후보에 함께 전달하며 결과에 적용 기준을 기록합니다. 감도를 바꾼 뒤 **새 분석**을 실행해야 합니다. 기존 결과의 영상만 재제작하면 그 결과에 저장된 감도를 사용합니다. ‘앱과 동일’ 비교 모드는 기본 감도를 고정합니다.

**미정 웃음 배정 (`laughter-listener-random-v2`):** 캐릭터 구간 모드에서 감지된 웃음의 화자가 미정이면, 해당 구간에 말하지 않는 캐릭터를 먼저 고르고 직전 2초의 발화도 가장 적은 후보 중 한 명을 무작위로 배정합니다. 모두 말하고 있으면 웃음과 겹치는 발화 시간이 가장 짧은 후보 중 무작위로 고릅니다. 단어 시각·중복 대사 마스크·발화 점수를 함께 사용하며 겹치는 발화 시간은 중복 합산하지 않습니다. 목소리 후보 점수가 높다는 이유로 현재 말하는 사람을 우선하지 않습니다. 후보가 모두 같은 조건이면 여러 캐릭터에게 무작위로 분배합니다. 원본 해시·웃음 구간 시각·후보로 난수 선택을 고정하므로, 같은 원본·구간·화자 설정의 영상 재제작에서도 배정이 유지됩니다. 영상 제작 시 화면에 연결된 캐릭터를 우선 대상으로 사용합니다. 원본에서만 남은 웃음과 분리 음성의 미정 웃음을 모두 처리합니다. `laughter_provisional`, `requires_review=true`와 선택 이유를 저장하며, 화면에는 ‘웃음 추정 배정’으로 표시합니다. 웃음 이벤트와 `[웃음]` 자막만 연결하고 원래 구간의 대사 화자·음성 점수는 유지합니다. 화자를 직접 미정으로 둔 구간도 웃음은 별도로 배정하되, 이미 확정된 웃음 화자는 유지합니다. 웃음 동안만 선택한 캐릭터가 웃고, 이후 원래 동작으로 돌아갑니다. 정지 옆모습 시트는 배정한 웃음 동안 정면 웃음 이미지로 전환합니다. 기존 분석도 **영상 다시 만들기**로 적용되며 STT·Claude를 다시 호출하지 않습니다. 앱 비교/모델별 실험 및 Android 재생은 이 정책의 적용 대상이 아닙니다.

**영상 웃음 진단:** 장면 설정의 **영상에 웃음 감지 수치 표시**를 켜면 MP4 상단에 원본·화자별 웃음 원점수 → 최종 판정 점수 / 실제 기준값, 검출·표정 ON/OFF, 입 움직임 신호와 탈락 이유를 표시합니다. 환경음·다른 발성 점수가 우세하거나 지속 시간·음량 조건을 통과하지 못하면, 원점수가 기준보다 높아도 최종 판정은 0일 수 있습니다. 점수는 웃음 확률(%)이 아닙니다. 미확정 웃음을 배정한 캐릭터에는 ‘웃음 추정 / 배정 ON’과 검출 구간 피크를 표시합니다. 추정 배정은 분리 음성의 측정 점수와 구분하며, 옆모습의 정지 표정도 별도로 구분합니다. 기존 결과는 **영상 다시 만들기**로 표시를 넣을 수 있습니다. 캐릭터 구간 분석의 원점수 기록이 없으면 원본·분리 음성에 대한 웃음 분석만 추가 계산하고 저장된 STT·화자·웃음 판정은 유지합니다. 앱 비교/모델별 실험의 이전 형식에서 없는 원점수는 ‘— / 원점수 기록 없음’으로 표시합니다. 영상은 원본 시각에 맞춰 진단을 그리므로 하이라이트로 잘라도 시각이 유지됩니다. 새 분석은 진단용 점수를 `character-tracks.json`에 함께 보관합니다. UI 기본은 표시이며 완성 영상에서는 체크를 끄고 재제작할 수 있습니다.

미확정 음성은 ECAPA 후보 점수·Nemotron 활동·주변 확정 발화를 이용해 같은 구간의 두 화자를 함께 배정합니다. 동점까지 남으면 후보 순서로 임시 배정하며 정확한 식별로 표시하지 않습니다. Claude는 전사와 후보 근거를 앞뒤 문맥과 함께 검토합니다. 원음은 이 검토 요청에 포함하지 않습니다. [Claude Messages의 JSON 출력](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)을 사용하며 구간 ID 누락·중복, 없는 화자, 동시 두 음성의 동일 화자 지정, 미완료 응답은 적용하지 않습니다. 오류 시 기존 임시 배정을 보존하고 실패를 표시합니다. `confidence`는 모델 자체 판단이며 보정된 정확도 수치가 아닙니다. 분리가 실패한 구간, 비음성, 화자 후보가 없는 경우와 사용자가 미확정으로 지정한 구간은 강제 배정하지 않습니다. 한 구간 안에 여러 화자의 대사가 남아 있으면 구간 단위 검토만으로 해결되지 않을 수 있습니다.

‘캐릭터·구간’의 **현재 설정으로 화자만 재검토**는 음성·분리·STT·주제 분석 캐시를 재사용하고 새 기록을 만듭니다. 직접 지정한 화자는 보호하며 임시/Claude 추정은 원래 음성 판단과 함께 표시합니다. 자막과 동작 트랙에 같은 배정을 적용하고, 영상은 수정된 기록으로 다시 제작합니다. API는 `config.speaker_review={mode:local|claude|conservative,model:claude-…}`이며 기존 기록 검토는 `reuse_job_id`와 `review_speakers`에 같은 설정을 보냅니다. 인증·모델 목록은 `/api/claude/connection`, `/api/claude/models`입니다. 구간별 `acoustic_speaker`, `assignment_source`, `requires_review`, `claude_review`와 결과의 `speaker_review` 호출·사용량·실패 정보를 보존합니다. 이 기능은 현재 웹 실험용이며 Android 적용은 별도입니다.

**입 움직임과 시선 (`dialogue-motion-v2`):** 자막에 사람이 언급되거나 말을 듣는다는 이유로 입을 움직이지 않습니다. 분리 음성의 실제 전사·단어 시각으로 `speech_mask`를 만들고 개별 음량·발화 감지와 결합합니다. 같은 발화가 여러 분리 음성에 남으면 시간대별 구절을 모아 비교해 한쪽 자막·발화 동작을 제외합니다. 문장 분할 차이, 4글자 이상 동일 구절, 한국어 음절·자모 오인식을 목소리 후보와 함께 판단합니다. 긴 동일 문장은 목소리 확신이 낮아도 중복을 정리합니다. 발화별 원본 화자 활동을 저장하므로 같은 구간 안에서 화자가 바뀌면 남기는 음성도 달라질 수 있습니다. 앞뒤 중복 구절에 이어진 심한 전사 오류는 양쪽 발화 시각 모두 원본 단독 화자 근거가 강한 경우에만 중복으로 추정합니다. 서로 다른 두 목소리가 뚜렷한 경우, 수동 확정한 서로 다른 화자, 3글자 이하 짧은 맞장구, 시간차를 둔 반복은 보존합니다. ‘캐릭터·구간 → 중복 대사 처리 내용 보기’에서 남긴 대사·제외한 대사와 판단 이유를 확인할 수 있습니다. 원래 `utterances`와 음성 배열은 보존하며 제외 내용은 `duplicate_dialogue`와 `duplicate_utterance_indices`에 기록합니다. 서로 다른 대사의 실제 겹침, 두 화자를 사용자가 직접 확정한 경우, 개별 웃음 동작은 유지합니다. 단어 사이 휴지는 입을 닫습니다. 기존 결과를 ‘영상 다시 만들기’로 재사용해도 적용됩니다. 이때 주제/클립의 원본 시간 범위를 유지하며 발화 ID를 갱신합니다.

장면의 **질문·말 걸기에 맞춰 상대 바라보기**(`Scene.auto_gaze=true`)는 화자의 입 움직임과 독립된 동작입니다. Claude 화자 재검토 응답의 발화별 `dialogue={utterance_index,intent,addressee}`를 사용합니다. 모델 검토가 없던 기존 결과에는 질문·호명·인사 문장 규칙을 적용하며 결과에 `text_rule`로 표시합니다. 3명 이상에서 상대를 좁힐 근거가 없거나 모델이 상대를 미확정으로 반환하면 임의로 고개를 돌리지 않습니다. 듣는 사람과 말하는 사람이 좌석의 화면상 위치에 맞춰 잠시 상대를 바라보고 기본 포즈로 돌아옵니다. ‘캐릭터·구간’에서 판단 구간과 상대를 확인할 수 있습니다. 방향별 입 파츠가 있는 기본 캐릭터는 옆모습에서도 말할 수 있습니다. 디자이너 5컷 시트의 옆모습에는 입 파츠가 없으므로 말하는 동안 정면 프레임을 유지하고, 듣거나 문장이 끝날 때 제공된 좌우 프레임을 사용합니다. 원본 이미지 파츠를 새로 생성하지 않습니다.

분리용 GPU 환경은 `.\server\setup-separation.ps1`로 설치합니다. PyTorch/torchaudio 2.5.1 CUDA 12.4를 모델 경로 옆 별도 폴더에 설치하고 `.lab-venv`에만 연결하며 앱 `.venv`는 변경하지 않습니다. 두 구간 작업이 CPU 감지와 GPU STT를 겹쳐 실행합니다. GPU 추론은 한 번에 하나이며 YAMNet·ECAPA도 공유 인스턴스별 잠금으로 보호합니다(Windows Keras 동시 호출의 네이티브 종료 방지). 분리→STT→Qwen 순으로 큰 GPU 모델을 반환합니다. 장치 실패 시 CPU로 몰래 바꾸지 않습니다.

구간별 캐시는 `segment_G*.json`, 분리 음성은 `stem_G*_[01].wav`, 공통 화자 기준은 `segment-plan.json`/`segment-base.npz`입니다. 단독 발화는 원본 PCM의 위치만 저장하고 듣기를 누를 때 짧은 WAV를 만듭니다. 같은 입력의 재분석은 PCM/분리 WAV를 하드링크로 재사용하고 수정 가능한 JSON은 별도로 저장합니다. 완료된 구간을 저장해 모델 오류 후 ‘저장된 구간부터 다시 시도’로 미완료 구간을 이어갑니다. 서버 종료 시 실험 세션은 정리되므로 필요한 결과는 내려받으세요.

`character-result.json`/`character-tracks.json`은 **v2 형식**입니다. 원본 시각·화자·자막과 구간별 20ms 말하기/웃음/음량을 담습니다. 웹 영상 합성은 v2를 직접 읽고 원본 오디오를 사용합니다. ZIP에도 v2 파일과 소스·설정이 포함됩니다. **Android 앱의 기존 v1 재생 형식에 자동 적용되지 않으며 앱 연결은 별도 단계입니다.** 구현은 `segment_core.py`, `segment_engine.py`, `segment_worker.py`, `separation.py`, `video_lab/characters.py`입니다. 검증은 `tests/test_character_segments.py`와 실제 CUDA/브라우저/MP4/수정/선택 재분석을 사용하는 `tests/character_segments_browser.py`입니다.

비교용 **‘앱과 동일’**은 `momo/inference/`의 실제 앱 백엔드 코드를 공유합니다. YAMNet 원음·음성 대역 재검사, Nemotron 연속 확률과 웃음 2차 화자 분석, Whisper 발화 병합·100ms 여유·원본 시각 자막, ECAPA 단독 발화 검사를 그대로 사용합니다. `app-result.json`·`app-tracks.json`을 영상에 직접 사용합니다. 이 모드는 기존 앱처럼 `[웃음]` 자막을 별도로 만들지 않습니다.

기존 6개 모델 선택·웃음 감도 비교는 **‘모델별 실험’**으로 전환합니다. 앱/캐릭터 구간 모드는 첫 5개 모델이 고정되며 주제 모델은 별도로 선택할 수 있습니다. 주제·하이라이트는 웹의 긴 원본용 문맥 분할 설정을 사용합니다. API는 `config.pipeline=segments|app|experiment`를 받습니다. 웹 기본은 `segments`이며 명시하지 않은 기존 API 호출은 호환성을 위해 `app`입니다. 구간 모드는 `mode=all|topics`, `segment_separation`, `laughter_captions` 옵션을 지원합니다. 구간 수정/재분석은 `POST /api/audio/jobs`의 `reuse_job_id`+`segment_action={segment_id,speaker_id,rerun}`이며, 실패 후 이어하기는 `reuse_job_id`+`resume_segments=true`입니다. 모두 세션 소유권·화자 ID·동시 작업 제한을 검증합니다. 과거 기록에 `pipeline`이 없으면 기존 실험 방식으로 취급합니다. 새 방식 적용에는 원본 재분석이 필요합니다.

**원본 하이라이트만 추출할 때:** 파일 선택 → 처리 기준과 최대 클립 수(1~10개) 지정 → **원본에서 하이라이트 추출**을 누릅니다. 배경·캐릭터 소스는 필요하지 않습니다. 캐릭터별 구간 모드는 공통 화자·목소리 기준까지 포함한 6단계를 실행하고, 기존 앱/모델 실험의 하이라이트 전용 모드는 VAD·웃음·STT·주제 4단계를 실행합니다. **원본 하이라이트** 탭에서 원본 시각, 선정 이유, 클립 재생과 다운로드를 확인합니다. 음성 파일은 M4A+SRT, 영상 원본은 실제 화면을 자른 MP4도 제공합니다. SRT는 각 클립 0초 기준이고 원본 파일은 수정하지 않습니다. 선정 기준은 웃음이 감지된 대화의 주제 경계이며 웃음 또는 전사가 없으면 0개일 수 있습니다. 캐릭터별 분석에서 분리 모델이 원본 웃음을 지워도, 원본에서 확인한 웃음은 화자 미확정 이벤트·자막·하이라이트 후보로 보존합니다. 화자가 미정인 이벤트도 추정 배정 정책에 따라 캐릭터의 웃음 동작으로 연결합니다. 결과는 서버 종료 전에 내려받으세요.

원본 입력은 기본 **10 GB / 6시간**까지 지원합니다. 2~3시간 녹음은 **원본 하이라이트 추출 → 결과의 ‘이 클립으로 영상 만들기’ → 배경·캐릭터 설정 → 영상 제작** 순서로 사용합니다. 앱 결과/움직임 데이터 형식에 맞춘 캐릭터 합성은 클립당 **10분 이하**이며, 긴 원본 전체를 곧바로 합성하지 않습니다. 브라우저 직접 녹음은 메모리에 임시 녹음을 모으므로 기존 **9분 50초** 제한을 유지합니다. 장시간 녹음은 파일로 준비해 업로드하세요. 긴 원본의 별도 OpenAI 화자 분리는 현재 지원하지 않으며, 하이라이트 추출에는 이 단계가 필요하지 않습니다.

업로드는 스트리밍으로 저장하며 진행률·취소를 지원합니다. PCM은 디스크 메모리 맵에서 구간별로 읽고, 전사는 최대 28초 음성 구간으로 나눕니다. 긴 전사문은 앞뒤 문맥이 겹치는 크기 제한 구간으로 주제 분석한 뒤 원본 발화 ID로 경계를 연결합니다. 이전의 1,200발화/60,000자 전체 길이 제한은 제거했습니다. 단계별 진행률은 처리한 프레임/구간 기준이며 남은 시간의 예측값은 아닙니다. 실제 대화가 긴 파일은 로컬 추론 시간 및 API 호출량이 늘어납니다.

`MOMO_LAB_MAX_AUDIO_BYTES`, `MOMO_LAB_MAX_SECONDS`, `MOMO_LAB_TEMP_ROOT`로 실험 서버의 제한과 저장 드라이브를 바꿀 수 있습니다. 기본 임시 저장소는 모델 디렉터리의 실제 경로 옆 `lab-temp/momo-audio-lab-*`이며, 모델 경로가 없으면 시스템 임시 폴더를 사용합니다. 현재 PC에서는 모델 폴더가 D:로 연결되어 있어 `D:\MOMO_Development\lab-temp`를 사용합니다. 업로드/PCM 변환 전에 여유 공간을 확인하며 정상 서버 종료 시 임시 파일을 정리합니다.

한 서버에서 동시 실험 1개, 임시 원본 업로드 12개·추가 소스 40개·실험 30개입니다. **디자이너 소스 업로드는 별도로 한 번에 80 MB**이며, 배경은 4096px 이하, 소스 ZIP은 400개 파일·압축 해제 후 150 MB까지 지원합니다. 묶음 안의 필수 파일이 잘못되면 해당 묶음 전체를 등록하지 않고 이전 소스 선택을 유지합니다. 필요한 결과는 **MP4 / 앱 적용 자료 ZIP / M4A / SRT / JSON 다운로드**로 별도 보관하세요. 새로고침하면 같은 세션의 실행 기록·진행 상태를 복구하지만 새 분석을 위한 원본은 다시 선택해야 합니다. 영상만 재제작할 때는 서버에 남은 원본을 재사용합니다.

모델별 해석 차이:

- GPT Transcribe는 선택한 VAD의 최대 28초 구간별로 호출하며 **구간 시각**을 사용합니다. 단어 시각을 생성하거나 다른 모델의 정밀 시각인 것처럼 표시하지 않습니다. 로컬 Whisper와 Whisper-1은 단어 정렬을 사용합니다.
- [OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/speech-to-text)에 따르면 Whisper-1과 GPT-4o-transcribe-diarize는 **2027-02-26 종료 예정**입니다. 호환 시험용 옵션에 이를 표시했습니다. 현재 권장 전사 모델인 GPT Transcribe와 화자 라벨 모델은 서로 다른 기능입니다.
- YAMNet은 약 1초 창, AST는 5초 창으로 웃음을 분류합니다. 두 모델의 점수는 직접 같은 확률로 해석하지 않습니다. 기본 웃음 기준 0.1은 기존 YAMNet 기준입니다.
- 군집화 방식은 짧은 발화·겹친 발화에 한계가 있으며 선택한 화자 수는 군집화에만 적용합니다. 화자 라벨은 실험마다 달라질 수 있습니다. 목소리 벡터는 3초 이상의 단독 발화가 필요하며 다른 모델의 벡터끼리 비교하지 않습니다.
- 실험용 Qwen은 빠른 비교를 위해 **추가 추론 꺼짐**이 기본입니다. 체크박스로 켤 수 있으며 앱의 기존 Qwen 추론 설정과 구분해 결과 설정에 기록합니다.
- 긴 원본의 각 Qwen 문맥 구간에는 원본 발화 ID 범위와 필수 시작 ID를 명시합니다. 경계 검증에 실패한 로컬 응답만 한 번 교정 요청하며, 재검증에도 실패하면 해당 단계에서 중단합니다. 잘못된 ID를 임의 보정해 클립을 만들지 않습니다. 시도 횟수는 결과의 `requests`, 잘못된 응답은 작업 폴더의 `topic-invalid-*.json`에 남습니다. OpenAI 요청의 재호출 정책은 바꾸지 않습니다.
- **웹 실험의 로컬 STT·Qwen은 GPU가 기본**입니다. Whisper는 CUDA/float16, Qwen은 실행기에서 감지한 GPU(CUDA 우선)를 사용합니다. 현재 PC의 RTX 3070에서 Whisper는 CUDA, 설치된 Qwen 실행기는 Vulkan으로 실행됩니다. STT가 끝나면 모델 메모리를 반환하고 Qwen을 로드합니다. 결과 화면과 JSON의 `stages.*.data.execution`에서 실제 장치·정밀도·Qwen GPU 레이어 수를 확인할 수 있습니다.
- Windows에서 긴 STT가 99% 부근에 종료되는 구형 실행기 문제를 막기 위해 웹 실험 환경은 **CTranslate2 4.8.5**를 별도로 고정합니다. `.\server\setup-audio-lab.ps1`로 설치합니다. 4.7.2 미만이면 모델을 로드하기 전에 업데이트 안내를 표시합니다. 완료된 단계는 `checkpoint.json`으로 보관하고, 비정상 종료 시 실패 단계·종료 코드·부분 결과를 표시합니다. 하이라이트 0개로 정상 완료한 경우와 분석 실패를 구분합니다.
- GPU 초기화 실패는 오류로 표시하며 CPU로 자동 전환하지 않습니다. CPU 비교 실행은 프로젝트 루트에서 `.\server\topic-lab.ps1 -Restart -Device cpu`, GPU 복귀는 `.\server\topic-lab.ps1 -Restart -Device gpu`입니다. 직접 Python으로 실행할 때는 `MOMO_LAB_DEVICE=gpu` 또는 `cpu`를 지정합니다. Windows CUDA DLL 경로는 실행기의 `-CudaRoot`가 `MOMO_CUDA_LIBRARY_ROOT`보다 우선합니다. 둘 다 없으면 모델 실제 경로 옆 `cuda-runtime`을 탐색합니다.
- 앱 모드의 Nemotron도 선택한 GPU/CPU를 사용하며, 1·2차 화자 분석이 끝나면 GPU 모델을 반환한 뒤 Whisper를 로드합니다. VAD·YAMNet·ECAPA는 앱처럼 CPU입니다. 모델별 실험의 기존 화자 어댑터는 CPU입니다. 웹 실험과 앱 worker는 같은 GPU 메모리를 공유합니다.

## 전사문만 비교하는 테스트 화면

텍스트만 넣는 이전 실험 화면은 **http://127.0.0.1:8770/text** 에서 사용할 수 있습니다. 실행 명령은 같습니다. 터미널을 유지하고, 종료는 `Ctrl+C`입니다. 기존 앱 서버와 동시에 켤 수 있습니다.

```powershell
.\server\topic-lab.ps1
```

`server` 폴더 안에서는 `.\topic-lab.ps1`입니다. 포트 변경은 `-Port 8771`로 지정합니다.

1. 우측 상단 **API 키 연결**에 OpenAI API 키를 입력합니다. [키 발급 페이지](https://platform.openai.com/api-keys)를 이용하며 로그인 아이디는 필요하지 않습니다. Project ID / Organization ID는 필요한 계정에서만 지정합니다.
2. 실제 `/v1/models` 응답에서 모델을 선택하거나 ID를 직접 입력합니다. 목록은 텍스트 모델 후보이며 모든 모델의 Responses·Structured Outputs 지원을 보장하지 않습니다. Models 읽기가 제한된 키는 직접 입력할 수 있습니다.
3. **샘플**, 전사문 붙여넣기 또는 **파일 열기**로 `transcript.json`/TXT를 넣고 **이 모델로 분석하기**를 누릅니다. 샘플 대화·시간·웃음 점수는 작성한 가상 데이터입니다. 결과를 미리 만들어 표시하지 않습니다.
4. 다른 모델을 골라 다시 실행한 후 **모델 비교**에서 주제 경계·제목·이유·시간·토큰을 비교합니다. 최근 10개 결과를 페이지 메모리에 유지하며 새로고침하면 사라집니다. **JSON 내려받기**로 선택한 결과와 입력·설정·실제 사용 토큰·request ID를 보관할 수 있습니다.

키는 브라우저 저장소·소스·결과 JSON에 기록하지 않습니다. 화면에서 넣은 키는 브라우저 세션별 로컬 서버 메모리에만 유지되며 연결 해제·서버 종료·12시간 미사용 시 만료됩니다. 선택적으로 `server/.env`에 `OPENAI_API_KEY`, `OPENAI_PROJECT_ID`, `OPENAI_ORG_ID`를 설정하거나 실행 환경 변수로 전달할 수 있습니다. 환경 변수는 `.env`보다 우선하며 `.env`는 Git 제외 대상입니다. 환경 설정을 사용 중일 때 연결 해제는 해당 브라우저 세션만 해제합니다.

**테스트 범위:** `momo/topic_lab.py`가 OpenAI [Responses API의 Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)로 실제 요청합니다. 기존 `highlights/topics.py`의 프롬프트·경계 검증·클립 선정 함수를 공유합니다. GPT에는 발화 ID와 텍스트를 보내며 시간은 입력 전사에서 계산합니다. 결과 저장 요청은 `store: false`로 설정합니다. 실행 버튼을 누르면 전사문이 OpenAI로 전송되고 API 사용량이 발생합니다. 오류·시간 초과 시 자동으로 재호출하지 않습니다.

일반 텍스트는 한 줄을 한 발화로 처리하고 **주제 분할만** 표시합니다. 시간 JSON은 아래 형식이며 `id`는 연속 정수, `startMs`·`endMs`는 밀리초입니다. 기존 서버의 `transcript.json`을 그대로 열 수 있습니다. 발화 1,200개 / 대화 텍스트 60,000자 / 입력 파일 800 KB까지 지원하며, 선택 모델의 문맥 한도가 더 작으면 입력을 줄여야 합니다.

```json
{"utterances":[{"id":1,"startMs":0,"endMs":4000,"text":"주말 여행 어디로 갈까?"},{"id":2,"startMs":4000,"endMs":8000,"text":"바다 보러 가자."}]}
```

**웃음 후보 연결**에 YAMNet 구간 배열을 추가하면 기존 규칙(기본 웃음 0.1 이상, 음악 제외, 겹치지 않는 구간 최대 3개)으로 하이라이트를 계산합니다. 후보가 없으면 임의의 점수·클립을 만들지 않습니다. `durationMs`를 지정하면 후보 종료 시각이 그 범위를 넘지 않아야 합니다. 후보 배열 예시는 다음과 같습니다.

```json
[{"startMs":5000,"endMs":6500,"laughter":0.7,"music":0.02}]
```

이 페이지는 주제 모델 비교용이며 STT·화자 분리·YAMNet을 새로 실행하거나 M4A·MP4를 생성하지 않습니다. 기존 앱 자동 분석은 계속 Qwen을 사용합니다. 웹 구현은 `momo/topic_lab_web/`, 검증은 `tests/test_topic_lab.py`입니다. API 오류·키 누출 방지·시간/ID 검증·모델 변경·기존 클립 선정 규칙을 검사합니다.

## 현재 PC에서 실행

프로젝트 루트의 PowerShell에서 실행합니다. 아래 CUDA 경로는 이 PC에 설치된 라이브러리 위치입니다.

```powershell

.\server\backend.ps1 status
.\server\backend.ps1 stop
```

`start`는 별도 창 없이 API·분석 worker·정리 작업을 백그라운드에서 실행합니다. Android Studio를 닫아도 유지됩니다. `status`가 `ready`, `analysis_ready: true`, `data_origin: inference`이면 실제 분석 준비가 완료된 것입니다. 시작 명령의 성공만으로 모델 준비 완료를 의미하지 않습니다. 준비 중이면 잠시 뒤 확인하고, 계속 준비되지 않으면 `data/worker.log`, `data/supervisor.log`를 확인합니다.

```powershell
cd server
.venv\Scripts\python.exe manage.py start --device cuda --cuda-root D:\MOMO_Development\cuda-runtime
.venv\Scripts\python.exe manage.py status
.venv\Scripts\python.exe manage.py stop
```

`run`은 포그라운드 실행, `--device cpu`는 CPU 실행입니다. 작업 디렉터리에 관계없이 기본 데이터 위치는 `server/data/`입니다. `--data-dir`, `--models`, `--port`로 별도 시험 환경을 지정할 수 있습니다. 별도 데이터 디렉터리를 썼다면 상태 확인·종료에도 같은 `--data-dir`를 지정합니다. 기존 `tools/start_local.py`는 호환용으로 이 실행기를 호출합니다.

## 자동 하이라이트

앱에서 새 녹음을 정상 저장하면 Room에 요청을 기록하고 WorkManager가 업로드·상태 조회·다운로드를 수행합니다. 서버가 꺼져 있으면 원본과 요청을 유지하고 연결을 재시도합니다. 이전에 보관하던 녹음 전체를 자동 업로드하지 않습니다. 앱의 수동 찾기 버튼과 기기 내 분석 서비스는 제거했습니다.

분석 구현은 `momo/highlights/`입니다. **YAMNet 웃음 기준 0.1 → Whisper 한국어 STT → Qwen3.5-4B의 대화 주제 분할 → 웃음이 포함된 주제 최대 3개 → FFmpeg AAC/M4A·SRT 저장** 순서로 실행합니다. Whisper는 영상 분석 worker가 로드한 모델을 공유하고 주제 모델은 기본 CPU를 사용합니다. 웃음 또는 유효한 전사가 없으면 빈 결과로 정상 완료합니다.

이 PC에는 모델을 준비했습니다. 다른 Windows PC에서는 기존 PC 도구의 고정 모델 캐시를 준비한 뒤 서버 폴더에서 한 번 실행합니다. `--source-cache`, `--assets`, `--destination`으로 준비 경로를 지정할 수 있습니다.

```powershell
.venv\Scripts\python.exe -m momo.prepare_highlights
```

준비 시 YAMNet·라벨과 Qwen 모델·llama.cpp b12110 런타임을 `data/models/highlights/`로 복사합니다. 이후 서버 실행에는 앱 폴더나 PC 도구가 필요하지 않습니다. 이 PC의 모델 폴더는 `D:\MOMO_Development\models`에 연결되어 있습니다. 런타임 중 모델을 다운로드하지 않습니다. 기본 한도는 80MB·2시간, 작업 제한 시간은 30분입니다. 2시간 녹음을 30분 안에 처리하는 성능은 검증하지 않았습니다.

| API | 용도 |
|---|---|
| `POST /v1/highlights` | `audio`, `sha256`, `options` multipart 업로드. `Idempotency-Key`로 중복 요청 방지 |
| `GET /v1/highlights` | 해당 설치의 하이라이트 작업 목록 |
| `GET /v1/highlights/{jobId}` | 상태·단계·진행률 |
| `GET /v1/highlights/{jobId}/result` | 제목·구간·크기·SHA-256이 담긴 결과 |
| `GET /v1/highlights/{jobId}/files/{name}` | 인증 후 M4A·SRT·전사 파일 다운로드 |

옵션은 `{"consent_version":"automatic-highlights-v1"}`이며 한국어·기준 0.1·최대 3개가 기본 고정값입니다. 취소·삭제·실패 작업 재시도는 기존 `/v1/analyses/{jobId}/cancel`, `DELETE /v1/analyses/{jobId}`, `/v1/analyses/{jobId}/retry` 수명주기 API를 공유합니다. 앱에는 수동 분석·취소 UI를 두지 않습니다.

서버 파일 위치는 `data/objects/highlights/<jobId>/<lease>/clip_N.m4a`, `clip_N.srt`, `transcript.json`입니다. 결과 manifest는 `data/objects/results/<jobId>/<lease>.json`입니다. DB에 완료 상태와 파일 목록을 함께 게시하며 유효 lease를 잃은 작업의 출력은 공개하지 않습니다. 서버 업로드 원본은 작업 종료 후 24시간, 하이라이트 파일·결과는 30일 뒤 정리합니다. 모든 조회는 설치 소유권을 확인합니다.

앱은 내려받은 클립의 크기·SHA-256을 검증하고 `noBackupFilesDir/highlights/server-<jobId>/`에 저장합니다. 전체 다운로드 후 `index.json`을 마지막에 기록하므로 중단된 파일이 목록에 나타나지 않습니다. 다운로드된 클립은 서버 보관기간과 별개로 유지됩니다.

## 설치별 인증

자동 하이라이트에도 아래 설치 인증을 그대로 사용합니다.

1. 앱이 서버 주소별 UUID와 별도의 256비트 무작위 인증키를 생성합니다. Android Keystore로 암호화해 백업 제외 영역에 원자적으로 저장한 뒤 서버에 요청합니다. APK에 공용 계정이나 인증키를 넣지 않습니다.
2. `POST /v1/auth/installation`에 `installation_id`, `installation_secret`을 보내면 서버가 설치 전용 소유자를 만들고 access/refresh token을 발급합니다. 같은 ID와 키로 다시 요청하면 같은 소유자를 사용합니다. 서버에는 키의 SHA-256 해시만 저장하며 ID만으로 인증할 수 없습니다.
3. access token은 15분, 세션은 30일입니다. 앱이 refresh token을 교체하며, 세션 만료 후에도 같은 설치 키로 자동 재인증합니다. 앱·WorkManager의 동시 요청도 인증과 갱신을 직렬화합니다.
4. 업로드·목록·조회·재시도·취소·삭제는 설치별 소유권을 확인합니다. `installations.revoked_at`이 설정된 설치는 새 인증·토큰 갱신·자료 접근을 거부합니다. 자동 등록은 IP당 분당 10회로 제한합니다.

앱 업데이트와 재실행은 ID를 유지합니다. 앱 데이터 삭제·삭제 후 재설치·서버 주소 변경은 새 ID를 만들며 이전 설치의 서버 자료를 자동 복구하지 않습니다. 하드웨어 ID나 Android 계정에 연결하지 않습니다. 이 인증은 설치 키 소유를 확인하며 실제 차량이나 정품 앱 여부를 검증하는 기능은 아닙니다.

기존 녹음·영상·인물 정보·다운로드된 분석은 유지됩니다. 이전 개발 계정의 서버 작업은 해당 계정 소유로 남습니다. 아직 진행 중인 분석은 원본을 새 설치 소유로 다시 요청하고, 기존 취소 대기는 로컬에서 종료합니다. 이전 계정 로그인 API/CLI는 관리 호환용으로 남지만 새 로컬 서버가 개발 계정을 자동 생성하지는 않습니다. 기존 `local-development.json`과 DB는 보존하며 새 설정 파일에는 JWT 서명키만 생성합니다.

로컬 실행기는 `127.0.0.1`에서만 수신합니다. 실차·다른 PC에 공개하는 서버는 별도 HTTPS 구성이 필요합니다. Release 앱은 HTTPS 주소와 서명을 따로 준비합니다.

## 구성과 검증

같은 저장소 안에서 `app/`은 Android 클라이언트, `server/`는 Python 백엔드, `contracts/`와 `tests/fixtures/`는 API 명세·공통 검증 자료입니다. 별도 Git 저장소로 나눈 구성은 아닙니다. 백엔드는 앱 파일이나 ADB에 접근하지 않습니다.

새 PC에는 Python 3.11, uv, FFmpeg/ffprobe를 설치하고 서버 폴더에서 `uv sync --frozen --extra inference`를 실행합니다. 모델과 CUDA는 [기존 준비 절차](../docs/app-animation.md#다른-pc의-서버-준비)를 따릅니다. `--fixture`는 자동화 테스트용 가짜 분석으로 실제 시연에는 사용하지 않습니다.

서버 검사는 서버 폴더에서 `.venv\Scripts\python.exe -m pytest`로 실행합니다. 로컬 구성은 SQLite와 별도 worker를 사용합니다. 운영용 PostgreSQL·Redis·Celery 구성은 [배포 안내](../docs/MOMO_DEPLOYMENT.md)를 따르며 운영 환경 통합 검증은 별도입니다.

2026-11-06 자동 하이라이트 전환 검증: 서버 테스트 83개, Android 단위 테스트 40개, 기기 테스트 20개 통과. Debug/테스트 APK 빌드 성공, Lint 오류 0개·경고 59개입니다. 합성 한국어+공개 웃음 약 25초 입력이 자동 업로드되어 서버에서 22.912초 M4A 1개를 만들었습니다(`data_origin: inference`).

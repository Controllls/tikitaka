# 이동기록 구현 기술과 처리 로직

기준일: 2026-11-12 · 대상: `HD_project`의 현재 작업 파일 · Figma 적용 전 기준

이 프로젝트는 차량용 Android 앱, 앱 전용 분석 API, PC 웹 실험 도구로 구성된다. 앱에서 녹음한 뒤 서버로 분석을 요청하고 결과를 보관하는 흐름이 구현되어 있다. 웹 실험 도구는 여기에 구간별 음원 분리, 화자 재검토, 중복 발화 억제와 디자이너 소스 교체를 추가한 별도 실행 경로다. **웹에서 검증한 기능이 Android 앱에 모두 연결된 상태는 아니다.**

여기서 ‘구현’은 코드와 호출 경로가 있다는 뜻이다. 실제 차량 검증, 외부 AI API 호출 성공, 마켓 심사 통과와 구분한다. 수치와 모델명은 현재 프로젝트 설정이며 최신 제품 권장값이나 공식 플랫폼 규격을 뜻하지 않는다. API 키·토큰·사용자 녹음 내용은 포함하지 않는다.

## 3 녹음 종료 후 자동 하이라이트

1. M4A 저장 완료 후 `AutomaticHighlights.recordingSaved()`가 Room에 요청 정보와 멱등 키를 기록한다.
2. 네트워크 연결 조건의 WorkManager 고유 작업을 `KEEP` 정책으로 등록한다. 같은 녹음에 대한 중복 예약을 줄인다.
3. 앱 설치 인증 후 원본 해시와 오디오를 `/v1/highlights`에 업로드한다.
4. 서버는 오디오를 16kHz PCM으로 디코딩한다.
5. YAMNet TFLite의 웃음 관련 6개 클래스 중 최대 점수를 구한다. 15,600샘플 창과 7,800샘플 간격을 사용한다. 후보를 **기준 0.1**로 묶는다.
6. Whisper가 원본 전체의 한국어 대화를 전사한다. 단어 시각과 발화 문장을 만든다. 영상용 발화 마스크와 독립적으로 전사한다.
7. Qwen이 전사 문맥에서 대화 주제 경계를 추정하고 웃음 후보를 해당 주제 구간에 연결한다. 기본 최대 3개를 선택한다.
8. FFmpeg로 선택 구간의 M4A와 SRT, 전사 JSON을 만든다.
9. 앱이 작업 상태를 약 5초마다 확인하고 완료 클립의 해시·길이 등을 검증해 내부 저장소에 보관한다.

정상 진행은 빠른 폴링을 사용하고, 통신 오류는 30초부터 지수형 재시도를 사용한다. 한 worker 실행은 약 8분 후 양보하고 저장된 작업을 이어간다. 연결 오류 재시도는 코드상 96회 미만이며 영구 오류·원본 삭제 등은 종료한다. 서버가 꺼져 있어도 원본 녹음은 유지한다.

현재 선택은 ‘웃음을 포함한 대화 주제’ 기준이다. 웃음 없는 대화의 재미를 종합 평가하는 시스템이나 인기 예측 모델은 아니다. 결과가 0개인 경우도 정상 결과일 수 있다.

근거: `app/.../AutomaticHighlights.kt`, `server/momo/highlights/pipeline.py`, `selection.py`, `topics.py`.

## 4 앱 영상 분석 서버의 AI 흐름

`server/momo/inference/pipeline.py`의 `Pipeline.run()`이 실행 경로다.

| 순서 | 기술 | 입력 → 출력과 역할 |
| --- | --- | --- |
| 1 | FFmpeg 디코딩 | 원본 오디오 → 16kHz PCM, 길이·형식 확인 |
| 2 | Silero VAD + YAMNet | 음성 존재 확률, 말·웃음·환경음·무음과 에너지 분류 |
| 3 | Nemotron ONNX | 구간별 화자 활동 확률. 원본의 시간축에 맞춰 화자 트랙 구성 |
| 4 | 웃음 재검사 | 음성 관련 구간을 남긴 입력을 다시 화자 분석해 웃음 화자 활동 복구 |
| 5 | Faster Whisper | 말 구간의 한국어 전사와 단어 시각 |
| 6 | 결과 결합 | 이벤트, 자막, 화자 목록, 활동 확률·웃음 활동·혼합 음성 에너지 트랙 생성 |
| 7 | ECAPA-TDNN | 겹치지 않는 발화에서 화자별 192차원 목소리 특징 추출 |

분석 결과와 동작 트랙은 별도 JSON이다. 타임라인은 원본 시간에 고정되며 기본 20ms 간격의 정보를 렌더링에 사용한다. 목소리 특징이 부족한 화자는 경고와 기본 캐릭터로 처리한다.

### 웃음 감도 0.1만으로 설명할 수 없는 이유

자동 하이라이트의 단순 웃음 후보 기준과 영상 분석의 웃음 판정은 다르다. 영상 분석은 다음 조건을 조합한다.

- 웃음 점수와 다른 발성·비음성 소음 점수의 상대 크기.
- 최대 점수와 연속 창 수를 통한 최소 지속 조건.
- 원본과 음성 대역 필터 결과를 비교하는 작은 웃음 복구.
- 실제 오디오 에너지와 무음 여부.
- 웃음 검출 후 별도로 수행하는 화자 소유권 판단.

따라서 점수 기준을 낮춰도 소음 대비·지속 시간·화자 매칭에서 탈락할 수 있다. STT는 주로 말을 글로 옮기는 역할이며 웃음 검출기의 대체물이 아니다. `[웃음]` 표시는 별도 웃음 이벤트를 자막에 결합하는 방식이다.

근거: `server/momo/inference/acoustic.py`, `laughter.py`, `fusion.py`, `asr.py`, `voice.py`.

## 5 등록 인물과 화자 매칭

녹음 내 ‘S1, S2’와 사용자가 등록한 ‘인물 이름’을 연결하는 기능이다. 차량 사용자 인증이나 실시간 좌석 식별로 쓰지 않는다.

1. 인물 프로필에 이름과 캐릭터를 저장한다.
2. 등록용 분석에서 한 사람이 말한 충분한 음성을 골라 ECAPA 특징을 보관한다. 프로필 검증은 6~30초 음성, 정규화된 192차원 벡터를 요구한다.
3. 새 영상 분석의 화자 특징과 같은 모델 버전의 등록 특징을 코사인 유사도로 비교한다.
4. 1위 유사도 **0.65 이상**, 2위와 차이 **0.08 이상**일 때 후보로 채택한다. 여러 화자가 같은 인물로 충돌하면 매칭을 해제한다.
5. 일치하지 않거나 음성이 부족하면 새로운 사람과 기본 캐릭터를 사용한다.
6. 영상에는 처음 감지된 최대 4명을 배치한다. 좌석은 발화 순서 기반이며 실제 좌석 위치를 추론하지 않는다.

인물과 목소리 벡터는 Android Keystore 기반 AES-GCM 파일에 저장된다. 위 기준은 프로젝트 초기 설정으로 실차 한국어 정확도 보증 수치가 아니다.

근거: `app/.../momo/people/People.kt`, `PeopleRepository.kt`, `PeopleViewModel.kt`.

## 6 Android에서 영상을 만드는 방식

현재 영상은 생성형 모델이 매 프레임 그림을 그리는 방식이 아니다. **디자이너가 만든 배경·차량·캐릭터 파츠를 오디오 분석 타임라인에 따라 합성한다.**

- `FixedPreset`이 APK의 고정 배경·차량·캐릭터 소스를 준비한다.
- `PeopleScene`이 분석 화자와 캐릭터를 연결한다.
- `MotionEngine`이 현재 이벤트, 화자 활동, 음성 에너지, 웃음 상태로 입 벌림·흔들림을 계산한다.
- 입 모양은 음소별 정밀 립싱크가 아니라 에너지와 주기 함수 기반 동작이다.
- `SceneRenderer`가 캐릭터 파츠와 차량·자막을 Canvas에 그린다.
- Media3 Transformer가 배경 영상과 CanvasOverlay, 원본 음성을 합쳐 H.264/AAC MP4를 만든다.
- 출력은 **540×960, 30fps**이며 앱 창의 1700×1184dp와 별개의 영상 규격이다.
- 인코딩 오류·취소 시 미완성 결과를 제거하고 완성 MP4의 비디오·오디오 트랙을 검사한다.
- 앱의 실제 내보내기 화면은 `Movies/이동기록`을 사용한다. 별도 `VideoComposer.publish()` 보조 함수에는 `Movies/MOMO`가 남아 있으나 현재 화면의 내보내기 경로와 구분해야 한다.

분석 JSON이 기기에 남아 있으면 서버에 다시 올리지 않고 영상을 다시 만들 수 있다. 최초 분석과 목소리 등록에 필요한 분석은 서버 연결이 필요하다.

| STT·자막 | Whisper small | Whisper base/tiny, OpenAI 전사 어댑터 | 텍스트·단어 또는 VAD 구간 시각 |
| 화자 분리 | Nemotron | ECAPA 군집화, X-vector 군집화, OpenAI 화자 전사 어댑터 | 화자별 구간·활동 |
| 목소리 특징 | ECAPA-TDNN | X-vector | 192차원 또는 512차원 특징 |
| 주제·하이라이트 | Qwen3.5-4B | OpenAI 모델 목록/직접 모델 지정 | 주제 경계·웃음이 포함된 클립 |

OpenAI API 키는 웹 실험 서버 연결에서 사용한다. 앱 설치 토큰과는 별개다. 모델 목록·전사·주제 분석 요청 코드가 있으나 각 모델의 제공 상태·요금·정책은 실제 호출 시 확인해야 한다. 기존 코드에 적힌 서비스 종료 안내를 이 문서의 검증된 외부 사실로 재인용하지 않는다.

웹에는 세 실행 모드가 있다.

| 모드 | 역할과 제한 |
| --- | --- |
| `app` | 앱 기본 모델·판정과의 비교용. 음성 모델 및 감도는 앱 기준으로 제한 |
| `experiment` | 6개 기능의 모델을 바꾸는 비교용. 선택한 기능에 필요한 선행 단계도 실행 |
| `segments` | 캐릭터별 구간 처리. 기본 음성 모델에 분리·재검토·동작 정리를 적용. 주제 모델과 웃음 감도 등을 설정 |

카탈로그가 제시하는 기본 모드는 `segments`다. 요청 객체의 기본값은 `app`이므로 저장된 설정이나 요청에 명시한 모드를 함께 확인해야 한다. 세 모드는 완전히 같은 로직이 아니다.

## 8 웹 구간별 화자 처리

실행 경로: `segment_worker.py` → `segment_engine.py` → `segment_core.py`.

1. 원본을 디코딩하고 PCM을 메모리 매핑 파일로 보관한다.
2. 전체 음성의 발화·웃음 후보와 화자 활동을 먼저 분석한다.
3. 깨끗한 단독 발화에서 각 화자의 공통 목소리 기준을 만든다.
4. 음성을 짧은 처리 구간으로 나눈다.
5. 겹치거나 불확실한 짧은 구간에 한해 **SepFormer WHAMR 16k**로 두 음원 후보를 만든다. 두 후보가 반드시 두 사람이라는 가정은 하지 않는다.
6. 구간/분리 음원마다 음성·웃음·목소리 매칭·STT를 처리한다.
7. 구간 JSON과 음원을 캐시한다. 실패한 구간만 재실행하거나 화자를 수동 지정할 수 있다.
8. 로컬 임시 매칭 또는 선택한 Claude 재검토를 적용한다.
9. 중복 대사와 불확실한 겹침을 정리하고 캐릭터별 자막·입 동작·웃음·시선 이벤트를 생성한다.
10. 원본 시간축으로 합쳐 `character-result.json`·`character-tracks.json`을 출력한다.

작업은 두 개의 스레드로 일부 CPU 처리를 겹치게 하지만 모델을 공유하고 GPU 호출은 직렬화한다. ‘모든 모델을 캐릭터 수만큼 GPU에 동시에 올리는 병렬 처리’는 아니다. 분리 모델은 두 음원용이므로 여러 사람의 동시 발화·누출·왜곡은 여전히 한계다.

### Claude 화자 재검토

`speaker_review.py`의 `claude-speaker-review-v3`는 전사 문맥, 음향 근거, 수동 지정 예시를 Claude Messages API로 전달한다. 화자 S ID, 확신도, 한국어 이유, 질문/말 걸기 의도와 상대를 구조화된 응답으로 받는다.

원본 파형을 Claude에 보내 화자를 직접 알아내는 경로가 아니다. 대화의 흐름은 보조 근거이며 실명이나 실제 신원을 추론하지 않는다. 텍스트와 타임스탬프는 수정하지 않고 수동 지정을 우선한다. 불확실한 배정은 `requires_review`로 남긴다. 기본 설정은 로컬 재검토이며 Claude 모드는 모델 선택·API 키가 필요하다. 앞선 실제 실행에서 공급자 응답 형식 설정 오류가 있었으므로 ‘Claude 실호출이 항상 성공’으로 표시할 수 없다.

### 같은 대사로 두 캐릭터가 말하는 문제 억제

`dialogue_dedup.py`, `speech_ownership.py`, `dialogue_motion.py`가 담당한다.

- 겹친 구간의 동일·유사 전사 복제본을 정리한다.
- 전사가 서로 다르게 잘못 나왔어도 다른 두 목소리라는 근거가 없으면 겹친 시간에는 한 소유자만 선택한다.
- 서로 다른 확실한 목소리 매칭 또는 서로 다른 수동 지정이 있으면 실제 동시 발화를 보존한다.
- 자막과 입 동작이 같은 파생 발화 구간·단어 시각을 사용한다. 다른 사람 이름을 자막에서 언급하는 것만으로 그 사람의 입을 열지 않는다.
- 원본 오디오·원래 전사·음향 배열을 바꾸지 않아 재검토가 가능하다.

이 정책은 불확실한 분리 결과에서 중복 표현을 줄이는 선택이다. 근거가 약한 실제 동시 발화를 한 사람으로 축소할 가능성도 있으므로 진단·수정 UI가 남아 있다.

### 웃음 화자 미정 처리와 영상 진단

웃음이 검출됐지만 누구인지 모르면 `laughter_assignment.py`가 해당 구간에 말하지 않는 캐릭터를 우선한다. 직전 2초 발화량도 비교하고 동률 후보 사이에서 무작위 선택한다. 원본·시간을 시드로 사용해 같은 분석을 다시 렌더링할 때 선택이 유지된다. 모두 말하는 중이면 겹친 발화 시간이 가장 짧은 후보를 사용한다.

이는 사용자가 요청한 **표현용 임시 배정**이며 실제 웃은 사람을 확인한 결과가 아니다. 대사의 화자 매칭은 바꾸지 않는다. 웃음 점수·판정·화자 배정을 영상에 표시하는 진단 오버레이와 원점수 보완 경로가 있다. 낮은 감도만으로 해결되지 않는 점수·소음 대비·지속·배정 단계를 구분해 볼 수 있다.

### 질문·말 걸기의 고개 돌림

텍스트 규칙 또는 Claude의 대화 의도 결과에서 질문·직접 말 걸기와 상대를 추출한다. 두 명일 때 상대를 정할 수 있고, 여러 명은 이어지는 응답 등 문맥을 참고한다. 웹 `video_lab/gaze.py`가 좌석 좌표를 비교해 좌/우 포즈와 짧은 전환을 만든다. 질문 말미에서 응답 초반까지 최대 약 4초 구간을 사용하며 입 동작과 독립적이다.

## 9 디자이너 소스와 웹 영상 제작

- 배경, 캐릭터, 차량을 개별 파일·폴더·ZIP으로 추가한다.
- 기본 소스는 `server/assets/designer-defaults/`이며 `현대_공모전/source`에서 가져온 구성이다.
- 캐릭터 manifest+PNG 파츠 형식 외에 디자이너의 표정 시트 형식도 어댑터로 처리한다.
- 차량의 번호형 다중 레이어를 읽어 차체·좌석·안전벨트 등으로 합성한다.
- 장면 설정에서 캐릭터와 화자·좌석 연결, 크기·배치·배경을 조절한다.
- Pillow에서 프레임을 만들고 FFmpeg `libx264`로 540×960·30fps H.264/AAC 영상을 만든다. **웹 영상 인코딩 자체는 현재 NVENC가 아니다.**
- 긴 원본은 하이라이트를 먼저 추출하고 10분 이하 클립을 영상으로 만든다.
- 완성 MP4, 전사·자막, 분석·프리셋·소스 묶음 ZIP을 내려받는다. 키는 ZIP에 넣지 않는다.
- 분석을 재사용해 캐릭터·배경·배치만 바꿔 영상을 다시 만들 수 있다.

웹의 표정 시트·차량 레이어 확장 형식과 `character-*` v2 트랙은 Android 원래 렌더러와 자동 호환되지 않는다. ZIP 다운로드가 앱 적용을 완료하는 동작은 아니다.

## 10 서버 작업과 인증

### 회원가입 없는 설치 인증

앱이 임의 UUID와 독립적인 32바이트 난수 인증키를 만든다. Android 고유 하드웨어 ID나 차량 VIN을 계정으로 사용하지 않는다. 서버별로 분리하여 Android Keystore AES-GCM·원자적 파일 저장으로 보관한다.

`/v1/auth/installation`에서 설치를 등록/인증하고 접근 JWT와 갱신 토큰을 받는다. 접근 토큰은 15분, 세션은 30일이다. 서버에는 설치 비밀키와 갱신 토큰의 해시를 보관한다. 갱신 토큰을 회전하고 이미 사용된 토큰의 재사용은 해당 세션 계열을 폐기한다. 작업 조회·파일 다운로드에서 소유자를 확인한다.

이 인증은 설치의 연속성을 위한 것이다. 기기 변경·재설치 후 계정 복구나 다른 기기와 동기화하는 회원 기능은 없다. 기존 관리자용 로그인 API는 코드에 남아 있지만 앱의 일반 사용 흐름은 설치 인증이다.

### 작업 관리

`api.py`가 업로드·해시·옵션을 검증하고 작업을 예약한다. `jobs.py`는 멱등 키와 요청 지문, 작업 상태·진행률·취소·재시도·lease를 관리한다. `worker.py`가 추론과 산출물 게시를 수행한다. 완료 결과와 소스는 파일 또는 S3 저장소에 저장할 수 있다.

개발 실행은 SQLite와 로컬 디스패처를 사용할 수 있다. `production` 설정은 PostgreSQL과 outbox/Celery 디스패처를 요구한다. Redis는 작업 전달에 사용한다. 모델 버전과 체크섬을 고정해 준비하고 readiness에서 실행 준비를 확인한다. fixture 모드는 합성 결과 경로이며 AI 품질 증거가 아니다.

| API | 역할 |
| --- | --- |
| `/v1/auth/installation`, `/refresh`, `/logout` | 설치 인증과 세션 관리. refresh/logout은 `/v1/auth` 아래 |
| `POST /v1/analyses`, `POST /v1/highlights` | 영상용 분석 또는 하이라이트 작업 예약 |
| `GET /v1/analyses/{id}` 및 `/v1/highlights/{id}` | 상태·진행률 |
| `/v1/analyses/{id}/result`, `/tracks` | 분석 JSON·동작 트랙. tracks도 동일 작업 경로 아래 |
| `/v1/highlights/{id}/result`, `/files/{name}` | 클립 정보·산출물 |
| `/v1/analyses/{id}/cancel`, `/retry`, `DELETE /v1/analyses/{id}` | 작업 제어 |
| `/health/live`, `/health/ready` | 프로세스·추론 준비 상태 |
| 웹 `/api/audio/*`, `/api/video/*` | 실험 입력·설정·작업·소스·미리보기 |

웹 실험은 별도의 쿠키 세션·CSRF/요청 출처 확인을 사용한다. 외부 모델 키 연결도 웹 세션에 속한다. 앱 JWT API와 동일한 공개 운영 서비스라고 간주하면 안 된다.

## 11 저장 위치와 보관 범위

Android 내부 기준 경로는 `/data/user/<사용자ID>/com.example.hd_project/no_backup/`이다. 현재 에뮬레이터에서는 사용자 ID 10을 사용했으며 모든 기기에서 10으로 고정되는 것은 아니다.

| 자료 | 경로 또는 정책 |
| --- | --- |
| 앱 녹음 | `no_backup/recordings/*.m4a` |
| 녹음 제목 | 녹음 옆 제목 메타데이터 JSON |
| 앱 하이라이트 | `no_backup/highlights/server-<jobId>/` |
| 앱 분석·프로젝트 | `no_backup/momo-projects/<projectId>/`, Room DB에 작업 상태·인덱스 |
| 앱 완성 영상 | `no_backup/momo-videos/`, 미완성은 `.pending.mp4` |

| 앱 설치 인증 | 서버 주소 해시별 `momo-installation-*.bin`, AES-GCM |
| 내보낸 영상 | MediaStore `Movies/이동기록` |
| 서버 객체 | 기본 `server/data/objects/` 또는 설정된 S3 |
| 서버 모델 | 기본 `server/data/models/`; 이 PC는 외부 모델 폴더 연결 사용 |
| 웹 분석·캐시 | 설정된 lab 임시 루트 아래 작업 폴더: PCM, 진행률, 구간·결과 JSON, stem WAV, MP4, ZIP |
| 공식·Figma 원본 | `design/` 아래 개발 참고 자료. 제품 APK 리소스와 분리 |

서버 기본 보관 설정은 작업 종료 후 원본 24시간, 결과 30일이다. 실제 삭제에는 maintenance 실행이 필요하다. 앱에 내려받은 클립·영상과 원본의 수명은 별개다. 웹 임시 저장은 개발용이므로 영구 보관함으로 간주하지 말고 필요한 결과를 내보낸다. `no_backup`은 Android 백업 제외를 뜻하며 녹음 파일 자체가 전부 앱 수준 암호화된다는 뜻은 아니다.

## 12 현재 제한과 실행 장치

| 항목 | 현재 코드 기본값 |
| --- | --- |
| 앱/앱 API 업로드 | 80,000,000바이트 |
| 앱 자동 하이라이트 길이 | 최대 7,200초, 즉 2시간 |
| 앱 영상 분석 | 0.1초~600초, 즉 10분 |
| 웹 원본 업로드 | 10,000,000,000바이트, 최대 6시간 |
| 웹 캐릭터 영상 | 입력/클립 최대 600초 |
| 웹 개별 소스 업로드 | 80,000,000바이트, 원본 음성 한도와 별개 |
| 서버 작업 제한 시간 | 기본 1,800초 |
| 화자 표시 | Android 영상 최대 4명 |

웹에서 2~3시간 자료를 처리하도록 늘린 한도가 앱 자동 업로드까지 확장된 상태는 아니다. 96kbps 오디오의 크기는 한 시간에 대략 43.2MB이므로 컨테이너 부가 용량을 제외해도 2시간은 약 86.4MB다. 현재 앱 80MB 제한은 2시간 길이 제한보다 먼저 걸릴 수 있다.

GPU 기본 설정은 앱 서버 `inference_device=cuda`, 웹 `lab_device=gpu`다. Nemotron은 ONNX Runtime CUDA, Whisper는 CTranslate2 CUDA/float16 경로를 사용한다. YAMNet은 TensorFlow CPU이고 목소리 특징 등 일부 단계도 CPU다. GPU가 없을 때 조용히 CPU로 바꾸지 않고 오류를 보고한다. CPU 실행을 명시하면 Whisper int8 경로를 사용한다.

웹 구간 분리는 PyTorch CUDA 환경을 별도로 필요로 한다. 웹 실험 환경은 CTranslate2 4.8.5를 고정하고 Windows의 오래된 실행기 종료 오류 방지 검사를 포함한다. 앱 서버 기본 의존성 파일은 CTranslate2 4.6.0이므로 두 환경을 동일 버전으로 가정하면 안 된다. 기본 Qwen 주제 장치도 앱 하이라이트에서는 CPU 설정이다.

## 15 Pleos 규칙 반영과 검증 기록

공식 수치·공식 요구와 프로젝트 구현 선택은 `docs/PLEOS_CONNECT_AI_DEVELOPMENT_RULES.md`에서 구분한다. 1700×1184 등의 값은 앱 창의 dp 프리셋이다. 현재 900dp 레이아웃 분기와 영상 540×960px는 프로젝트 선택이다.

- 적용된 항목: 실제 창 너비 기반 재배치, 가로·세로 정적 레이아웃, 시스템/IME 인셋, 일부 상태 복원, `CarUxRestrictions` 구독, 제한/미확인 상태의 영상 차단, 제한 해제 후 자동 재생 방지, 장식 동작 중지, 오디오 포커스.
- 관련 규칙: SIZE-01~06, WIN-01~04, STATE-01~04, DRIVE-01~03, PERF-01, API-01. 각 규칙의 전체 통과 선언은 별도 검증 범위를 따른다.
- 직전 검증 기록: JVM 44개 통과, Android 계측 5개 통과. 12개 화면 프리셋×2개 밀도×4개 XML 화면의 **96개 정적 레이아웃 측정** 통과.
- 측정 환경: Pleos API 34 에뮬레이터. 홈 주요 액션까지 2,148ms, 별도 cold start TotalTime 2,559ms. Debug APK 113,693,120바이트. 차량 성능 보장값은 아니다.
- 실제 플랫폼 제한 구독과 영상 제한 경로, 홈 재생성, 인물 편집 회전 복원을 확인한 기록이 있다.
- 웹 중복 발화 수정은 관련 테스트 76개와 저장된 100초 입력 결과를 확인한 이전 작업 기록이 있다. 전체 음질 정확도 평가나 이번 문서 작성에서 재실행한 결과는 아니다.
- 이번 작업은 코드 호출 경로와 설정을 대조한 문서화이며 유료 모델 요청·사용자 원본 재분석·전체 테스트 재실행을 하지 않았다.

실차, FormFactorConsole 모든 실제 창, 전체 동적 데이터·키보드·GNB 조합, 모든 프로세스 복원, 통화/내비/Gleo 포커스 경합, 장시간 주행 녹음은 별도 검증 대상이다. 서비스 지역·앱 카테고리·CAR_SEATS 승인·최종 제출 이미지 조건도 미확정이다.

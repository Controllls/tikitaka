20페이지 — PRODUCTION FLOW
============================================================

20-1. '시동을 끄면 저장 확인 후 제작을 시작' [조건 누락]
파일 마감→정상 저장→자동 작업 접수는 구현돼 있다.
하지만 실제 시동 OFF 수신은19-4의 한계가 있다. 현재 앱을 설명하는 제목은
'녹음이 끝나면, 저장 확인 후 제작을 시작합니다'가 더 정확하다.
시동 OFF를 유지한다면 debug 에뮬레이터/실제 차량 연동 상태를 바로 함께 표시한다.

20-2. '같은 원음의 작업은 한 번만' [표현 보완]
자동 접수의 중복 방지는 있음. 그러나 사용자가 같은 원음으로 '새 버전 영상 만들기'를
명시적으로 실행할 수 있고, 새 renderGeneration을 만들어 다시 제작한다.
수정: '자동 제작 중복 접수 방지 · 사용자 요청 시 새 버전 제작 가능'.
이 문장이 자동 접수만 뜻한다면 잘못된 로직은 아니며, 재제작까지 금지하는
설명으로 읽히지 않게 범위를 한정하면 된다.
근거: EpisodeWork.kt:62-102.

20-3. '지금 바로 제작할 수 없으면 대기로 보존, 다음 실행 때 이어감' [조건 누락]
현재: 녹음 중/작업 시간 초과는 waiting 및 저장 지점부터 이어가기.
      queued/running/waiting은 다음 실행에서 재개.
      저장 공간/모델/코덱 등 일반 예외는 failed이고 사용자 재시도가 필요할 수 있음.
수정: '일시 대기는 저장 후 재개 / 제작 실패는 원음 보존 후 재시도'.
근거: EpisodeWork.kt:109-118,130-146.

20-4. '첫 녹음만 동승자 안내' [앱 동작 설명은 맞음, 의미 한정]
현재 앱의 최초 안내 흐름을 설명하는 것은 맞다.
이 문장이 '처음 한 번 동의하면 이후 다른 동승자의 동의도 필요 없다'는
뜻이 되지 않도록 '최초 안내 팝업 · 매 녹음 전 동승자 동의 확인 안내'로 쓰는 편이 정확하다.
법적 동의 요건을 새로 판단한 항목은 아니다.

유지해도 되는 내용
  - 원음 저장 성공을 확인한 뒤 기본 자동 제작.
  - 시작 전에 녹음만 보관을 고르면 녹음 탭으로 이동.
  - 저장 실패·무음·부분 복구는 자동 제작 제외.
  - 제작 상태와 완성 영상을 보관함에서 확인.
단, 실행 중 저장 후 탭 이동과 앱을 새로 켰을 때 정상 저장본 탭 복원은 다르다.
후자는 현재 별도 보완 대상이며 모든 재실행 화면 복원 완료를 주장하면 안 된다.

21페이지 — IN-CAR EXPERIENCE
============================================================

21-1. '주행 중에는 일시정지만, 종료는 주차 후 또는 시동 OFF' [현재 코드와 차이]
현재 화면: 주행 제한 상태에서 녹음 종료 버튼을 누르면 종료를 차단.
           일시정지뿐 아니라 재개/Gleo 조작도 제공.
별도 경로: 녹음 알림의 종료 버튼은 ACTION_STOP을 서비스에 직접 전달하고,
           서비스는 해당 요청에서 주행 제한을 다시 검사하지 않음.
따라서 모든 종료 경로에서 주행 중 종료를 막았다고 말할 수 없다.
시동 OFF 역시 debug/release 차이가 있다.
수정 예: '주행 중 조작을 줄이고 앱 화면의 수동 종료를 제한합니다.'
또는 원래 제품 정책을 유지하되 '전체 종료 경로 검증 필요'를 명시.
이 항목은 코드 경로 확인이며 이번에 주행 중 알림 종료를 실제 실행한 것은 아니다.
근거: TikiActivity.kt:387-390; RecordingService.kt:69-71,286-304.

21-2. '영상을 묻지 않고 자동으로 제작' [기본값 기준 맞음]
기본 녹음의 정상 저장 후 자동 제작은 구현돼 있다.
다만 녹음만 보관/저장 실패/무음/부분 복구는 예외다.
20페이지의 예외 설명이 있으므로 중대한 오류는 아니지만 독립 슬라이드로 쓰면
'정상 저장 시 기본 자동 제작'이 더 정확하다.

21-3. '캐릭터와 실제 대화 자막' [기능 존재, 품질 보장으로 읽히지 않게 보완]
실제 대화 STT 자막과 캐릭터는 구현돼 있다. 완전한 전사/화자 매칭을 보장하지 않는다.
최근 기존 결과에 sttStatus=partial이 있고 자막 시간/화자 배정 일부는 추정이다.
도입 예시 화면의 문장이 실제 생성 제목/자막이라고 표현하면 안 된다.
PDF 하단의 '실제 작동 시연과 구분' 표기는 올바르므로 유지한다.

22-3. FusedLocation [미구현 계획 + 필요한 판정 로직 누락]
PDF: 위치/측정 시각을 연결해 도심·주택가·집 앞 배경 선택.
현재: SDK/위치 수집/배경 선택 연결 없음. 고정 city-road-loop.mp4 사용.
기술상 주의:
  공식 SDK는 위도·경도·방향·신뢰도·시각 등의 위치 정보를 제공한다.
  이것만으로 도심/주택가/사용자의 집 앞이라는 의미가 자동 반환되는 것은 아니다.
  도시/주거 분류 데이터, 저장된 집 위치나 미리 정한 영역, 위치 정확도/미수신 처리,
  녹음 시간축과 위치 시각을 맞추는 앱 로직이 필요하다.
  영역 진입/이탈 알림 API가 있어도 어떤 영역이 '집'인지는 앱에서 정해야 한다.
수정: 현재 구현 표에서는 빼거나 '위치+지역 판정으로 배경 선택하는 확장안(미구현)' 표시.
공식 근거: [S2].

22-4. NaviHelper [가능한 기능이지만 현재 미구현]
PDF: 녹음 시작 후 내비 화면 복귀, 도착 이벤트로 기록 마무리.
현재: NaviHelper 의존성·호출·도착 리스너·녹음 종료 연결 없음.
기술 판정: 공식 문서에 Navigation 화면 요청과 onDestinationArrived가 있으므로
           지원하지 않는 API라고 비판하면 틀리다.
           다만 이벤트 전달은 내비 구현/상태의 영향을 받으며,
           목적지 도착이 시동 OFF나 주차 완료를 뜻하는 것도 아니다.
수정: '확장 검토: 내비 화면 연계 및 목적지 도착 이벤트 활용(미구현)'.

22-5. Gleo Interface [부분 구현과 검증 예정 구분 필요]
PDF: 음성으로 앱 기능 실행, 사용 중 녹음 정지 후 직접 재개.
현재:
  - TikiActivity의 Gleo 버튼 → 녹음 PAUSE → Gleo 듣기 요청 브로드캐스트.
  - 녹음은 직접 재개하도록 구현.
  - assets/schema.json과 GleoContract/HighlightsActivity의 기존 하이라이트
    조회·재생 액션도 있음. 따라서 'Gleo 코드가 전혀 없다'는 판단은 틀림.
  - schema의 호출어는 '이동 기록', 설명에는 옛 서버 분석 문구가 남아 있음.
  - 현재 티키타카 녹음 시작/종료/새 영상 제작 전체를 음성으로 제어하는
    action 정의는 없음. 실제 Gleo 호출 성공·음성 명령 실행 검증과 구분해야 함.
  - 사용자가 앱 버튼을 눌렀을 때의 정지와 모든 시스템 Gleo 호출을 자동 감지해
    정지하는 것은 다름. 모든 외부 호출 상황을 감지하는 연결은 확인되지 않음.
기술 판정: 앱에서 Gleo를 부르는 것과 Gleo가 앱 기능을 호출하는 것은 서로 다른 방향.
공식 Interface는 App Schema의 function과 Action/Callback 연결을 사용한다.
수정: 'Gleo 호출 전 녹음 일시정지·직접 재개 구현 / 현재 기능의 음성 명령 연동 검증 예정'.
근거: GleoLauncher.kt:21-26; TikiActivity.kt:108-110,430-433;
      assets/schema.json; GleoContract.kt; AndroidManifest.xml; 공식[S5].

수정: 현재 구현 목록에서 제외하거나 '음성 상태 안내 확장안(미구현)' 표시.

22-7. '대화에 근거한 제목과 장면 구성' [구현 수준을 과장할 가능성]

문제: 대화를 이해해서 새로운 제목·장소·장면을 생성하는 모델로 읽히면 현재와 다름.
수정: '웃음·대사 구간 기반 하이라이트 선택, 전사문 일부를 제목으로 사용,
       제공된 캐릭터·차량·배경 소스에 발화/웃음 타이밍 반영'.
이 PDF에는 GPT/Claude 사용이라고 적혀 있지 않으므로 그런 주장을 오류로 추가하지 않았다.
근거: LocalHighlightPlanner.kt:59-80; TikiScene.kt; MetadataEpisodes.kt:263-308.

22-8. '원음·자막·캐릭터·배경 영상 합성' [저장 결과 설명 보완]

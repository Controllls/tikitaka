## 4. 녹음에서 영상까지의 실제 처리 순서

1. 사용자가 녹음 시작을 누른다. 자동 제작 세션은 음성 서버 전송을 동의 화면에서 알린다. `이번에는 녹음만 보관`은 해당 세션의 선택으로 고정한다.
2. 포그라운드 서비스가 AAC/M4A 음성과 임시 세션 저널을 저장한다. 일시정지는 실제 인코더 구간을 닫고 마이크를 반납한다. 재개는 새 구간을 만든다.
3. 종료 시 AAC 패킷을 재인코딩 없이 하나의 M4A로 합치고, 재생 가능한 오디오 트랙·패킷·길이를 확인한 뒤 최종 이름으로 저장한다. 첫 AAC 패킷의 음수 시간은 인코더 지연으로 처리한다.
4. 저장 실패 시 임시 구간을 삭제하지 않는다. 복구 버튼은 읽을 수 있는 구간만 새 파일로 합친다. 부분 복구·비정상 종료·무음은 자동 제작하지 않는다.
5. 정상 저장이고 녹음만 보관이 아니면 `EpisodeWork.enqueue()`를 호출한다. 사용자 요청으로 보관 중인 녹음을 제작할 수도 있다.
6. 기존 서버 하이라이트 분석을 요청·복원하고, 완성 클립을 내려받는다. 하이라이트가 없으면 원음 보관 상태로 마친다.
7. 각 클립을 서버에서 화자·STT·소리 이벤트 분석한다. 이미 저장된 유효한 분석이 있으면 재사용한다.
8. 제작 시작 시 보관한 암호화 프로필 스냅샷으로 본인 목소리를 매칭한다. 불확실 화자는 해당 녹음 내에서 일관된 일반 캐릭터를 배정한다. 첫 화자를 무조건 본인으로 보지 않는다.
9. 디자이너 제공 2D 캐릭터 8종의 기본·말하기·웃음 스프라이트, 차량 레이어, 도시 배경으로 Media3가 MP4를 만든다. 파일 검증 뒤 자막과 메타데이터를 저장하고 보관함에 노출한다.

자동 제작 상태는 `queued / running / waiting / failed / completed / empty`로 보관한다. WorkManager의 녹음별 고유 작업과 서버의 기존 작업 ID를 재사용한다. 완료 영상은 이후 내 이름·캐릭터를 바꿔도 무효화하거나 다시 만들지 않는다.

## 6. Pleos 규칙 적용

**공식 요구·수치:** `docs/PLEOS_CONNECT_AI_DEVELOPMENT_RULES.md`의 6종 가로·세로 앱 창 dp, 실제 창·인셋 사용, 주행 제한, 상태 복원, 성능·권한·제출 기준을 기준으로 한다. 앱 화면 dp와 마켓 스크린샷 px를 혼동하지 않는다.

**이번 구현 선택:** 네이티브 View 계층을 실제 사용 가능한 창의 dp로 구성한다. 홈은 2영역/세로 배치, 보관함은 콘텐츠 폭에 따른 열 수, 캐릭터는 서로 다른 가로·세로 좌표계를 사용한다. 이 분기점은 공식 Pleos 수치가 아니다. 낮은 높이에서는 내용과 액션을 스크롤해 접근한다. 전체 화면을 하나의 그림처럼 확대·축소하지 않는다.

**규칙 ID:** SIZE-01~06, WIN-01·02·04, STATE-01~04, DRIVE-01~05, PERF-01, API-01. 이 목록은 적용 대상이며 모두 실차 통과했다는 표시는 아니다.

`CarUxRestrictionsManager`가 전달한 제한으로 영상의 실제 `start()` 경로를 차단한다. 상태 미확인 시 재생하지 않는다. 해제·복귀 후 자동 재생하지 않는다. 목소리 확인은 제한 해제 상태에서만 시작하며 제한 전환 시 진행 중인 확인을 취소해 기존 등록 정보를 유지한다. 새 Vehicle SDK 퍼미션이나 확인하지 않은 시동 API를 추가하지 않았다.

**환경:** minSdk 28, compileSdk/targetSdk 37, AGP 9.4.1, Gradle 9.6.0, Java 17 소스 호환, Pleos Vehicle 2.3.2, Media3 1.9.0, WorkManager 2.10.3, Room 2.7.2. 테스트는 PC의 Pleos API 34 에뮬레이터 user 10이다.

## 7. 검증 결과

최종 실행 결과와 측정값은 `build/reports/tikitaka/validation-summary.json`, 계측 로그는 `instrumentation.txt`, 빌드·Lint 로그는 `build-and-tests.txt`에 저장한다.

최종 실행: debug 앱·테스트 APK 빌드 성공, JVM 44개 통과, Android 계측 10개 통과·보조 디스플레이 1개 환경 제약으로 미실행. Lint는 오류 0개·경고 71개이며 경고를 모두 해결했다고 보고하지 않는다. 주요 4화면 × 12개 크기 검사에서 텍스트 잘림·가로 경계 이탈 0개다. 디버그 APK는 142,561,997바이트이며 최종 서명 제출물은 아니다.

검사한 내용:

- 녹음만 보관 선택과 이름 입력 초안이 Activity 재생성 후 유지되는지 확인.
- 실제 녹음 일시정지 후 다른 MediaRecorder가 마이크를 사용할 수 있는지, 직접 재개 후 하나의 M4A로 저장되는지 확인.
- 녹음만 보관이 EpisodeWork·자동 하이라이트 요청을 만들지 않는지 확인.
- AAC 구간 결합 후 타임스탬프가 단조 증가하고 원본 해시가 유지되는지 확인.
- 디자이너 캐릭터 8종의 프레임 렌더링, 실제 3초 MP4 인코딩·검증.

## 8. 남은 구현·확인 사항

1. **휴대폰 연결:** Figma에서 연결 방식이 미정인 선택 기능이다. 차량 앱의 진입·미연결 안내만 구현했다. QR 모바일 웹/별도 휴대폰 앱 선택 질문은 아직 답변을 받지 않았다. 연결 토큰·휴대폰 재생·공유 서비스를 구현 완료로 보고하지 않는다.
2. **시동 OFF 정상 종료:** 후속 작업에서 debug 에뮬레이터의 Virtual Console OFF를 정상 저장 경로로 연결했다. 적용·설치 상태와 검증 결과는 [시동 OFF 연결 기록](IGNITION_OFF_2026-11-12.md)을 기준으로 한다. 실제 대상 차량의 시동 신호 API, 승인 권한, 종료 유예 시간은 여전히 확인이 필요하다.
3. **실제 AI 품질:** 새 전체 자동 제작의 실음성·실서버 종단 검증, 실제 목소리 등록/매칭의 정확도, 동시 발화·웃음 화자 정답률은 미검증이다. 이번 파이프라인 검사는 합성 음성·저장된 분석을 사용했다.
4. **실험 웹과 Android 차이:** 웹의 SepFormer 구간 분리, Claude 문맥 화자 재검토, dialogue-motion-v3, 질문 상대를 향한 고개 돌림은 이번 UI 작업에서 Android로 포팅하지 않았다. 새 영상은 기존 Android MotionEngine과 제공된 표정 스프라이트를 사용한다. 좌우 이미지가 APK에 있어도 문맥 기반 고개 돌림이 완성된 것은 아니다.
5. **기존 API 제한:** 자동 하이라이트의 앱 전송 80MB·서버 최대 2시간, 클립 영상 분석 0.1초~10분 제한은 그대로다. 실험 웹의 10GB·6시간과 동일하지 않다. 긴 녹음의 제한 초과 시 원음은 유지되고 제작 오류를 표시한다.
6. **세부 화면·동작 일치:** 핵심 화면과 기능 상태를 연결했으나 Figma 모든 변형 상태, 캐릭터 순환의 지정 애니메이션 시간, 휴대폰 26상태, 제출 자료 전체를 일치 검증한 것은 아니다. 체크되지 않은 상태를 완료로 간주하지 않는다.
7. **실차·제출:** FormFactorConsole의 전체 화면·DPI 조합, 실주행 이벤트, 출시 지역·앱 카테고리·CAR_SEATS 권한 승인, 서버 공개 주소/TLS, 최종 서명 APK·마켓 이미지·심사 자료는 별도 확인이 필요하다. 디버그 APK는 제출용 최종 산출물이 아니다.

## 9. 확인 방법

- 현재 실행 화면: `MainActivity → tiki/TikiActivity`.
- 에뮬레이터에는 기존 앱을 삭제하지 않고 debug APK를 업데이트 설치했다. 서버 없이도 홈·원음·기존 영상·캐릭터·내 정보 화면을 확인할 수 있다.
- 새 실음성 분석에는 기존 백엔드를 실행해야 한다. Debug 기본 주소는 `http://10.0.2.2:8765/`이며 실차·공개 배포 주소는 별도 구성한다.
- APK: `app/build/outputs/apk/debug/app-debug.apk`.
- 레이아웃·캐릭터·MP4 검증 산출물: `build/reports/tikitaka/tikitaka-validation/`.
- 개발 중인 기능을 다시 검증할 때는 `TikiIntegrationTest`와 `PleosRuntimeTest`를 사용한다. 사용자 자료 대신 `androidTest` 합성 fixture를 사용하고 테스트가 만든 자료만 정리한다.

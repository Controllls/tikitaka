# 웹 영상 엔진의 티키타카 앱 연결

## 적용 범위

2026-11-12. 새 녹음의 자동 제작과 보관한 원음의 수동 제작을 웹의 최신 분석·영상 엔진으로 연결한다. 화면은 기존 Figma 흐름을 사용한다. 기존 녹음·완성 영상·이전 버전에서 이미 요청한 작업은 유지한다.

대상은 Pleos Connect 차량용 녹음/콘텐츠 앱, 가로·세로 창이다. 서비스 지역과 마켓 앱 카테고리는 미확정이다. SDK/권한 변경은 없다. 공식 규격은 `PLEOS_CONNECT_AI_DEVELOPMENT_RULES.md`를 적용하며, 아래의 모델·용량·작업 정책은 프로젝트 구현 선택이다.

## 실제 제작 흐름

1. 녹음 종료 → 기존 녹음 검증·영속 저장. 녹음만 보관, 실패/무음/부분 복구 처리 조건은 기존과 같다.
2. 앱이 제작 당시의 내 이름·선택 캐릭터·등록 목소리 특징을 기기에 암호화해 보관한다.
3. 설치 토큰으로 `/v1/episodes`에 원음 업로드. 서버는 요청 당시 모델 설정을 고정해 작업 큐에 넣는다.
4. 기존 웹의 `audio_lab/segment_worker.py`로 음성 구간, 웃음, 화자 트랙, 겹친 소리 분리, 구간별 STT, 대사 소유권·중복 억제, 웃음 배정, 주제·하이라이트를 처리한다.
5. 앱이 분석한 화자의 목소리 특징을 내려받아 등록 목소리와 **기기에서** 비교한다. 서버에는 화자 ID·표시 이름·캐릭터 ID만 전송한다. 등록한 목소리 벡터는 전송하지 않는다. 전송한 대화 원음에서 서버가 분석용 특징을 추출하는 것은 별개다.
6. `/v1/episodes/{analysisId}/render` → 웹의 `video_lab/render.py`가 디자이너 배경·캐릭터·차량, 말하기·웃음·고개 방향을 합성한다.
7. 앱이 MP4·미리보기 PNG·자막 JSON을 받아 크기·SHA-256·MP4를 검증한 뒤 보관함에 게시한다. 서버 생성 썸네일을 홈과 보관함에 표시한다.

웹 브라우저를 열어둘 필요는 없다. 앱은 `8765` API와 워커를 사용한다. `8770`은 개발용 웹 실험 화면이며, `8088`은 차량 콘솔/시동 신호 테스트 용도다.

## 웹 기능과 앱 동작

| 웹 기능 | 앱에서 사용하는 시점과 처리 |
| --- | --- |
| 긴 원음 업로드·분석 | 녹음 저장 뒤 서버 업로드. 새 경로는 10GB·6시간 한도, 기본 최대 하이라이트 3개. 이는 기술상 제한이며 6시간 성능 검증을 의미하지 않는다. |
| VAD·웃음 감지·구간 분리 | 원음 분석 때 웹의 동일 코드 실행. 웃음 감도 기본 0.1. |
| 캐릭터별 독립 음성 처리 | 음성 구간별 STT·웃음·음량 트랙을 처리하고 웹의 v2 캐릭터 트랙으로 렌더링. |
| 중복 대사 억제 | 대사 소유권·중복 억제 로직을 그대로 사용. 실제 겹쳐 말한 상황까지 무조건 한 명으로 줄이지 않는다. |
| 불명확한 웃음 배정 | 웹의 비발화자 우선 임시 배정 규칙 사용. 실제 웃은 사람을 확정한 결과는 아니다. |
| 문맥 기반 고개 돌림 | 웹의 `dialogue-motion-v3` 및 자동 시선 처리 사용. 제공된 좌우 이미지로 표시. |
| 화자 재검토 | 로컬/Claude 설정을 지원. 기본은 로컬. Claude는 서버에 유효한 키와 사용할 모델 ID를 설정해야 한다. |
| 6단계 모델 선택 | 서버 프로필로 관리. 기본 구간 모드는 모델 조합을 제한한다. 자유 모델 실험은 웹과 동일하게 `pipeline: experiment`를 사용하며 결과 품질·타이밍은 달라질 수 있다. |
| 디자이너 소스 | `server/assets/designer-defaults`에 설치된 현대공모전/source 기본 묶음 사용. 앱에서 고른 8종 캐릭터 ID와 연결. |
| 영상·자막 | 540×960, 30fps MP4. 자막은 별도 파일로 저장해 앱의 자막 켜기/끄기를 지원. |

분석 구간이 일부 실패하면 완성 영상으로 게시하지 않는다. 하이라이트가 없으면 성공적으로 분석한 빈 결과로 표시하고 원음을 보관한다. 자동 캐릭터 표시는 최대 4명이며 초과 화자의 음성과 자막은 유지된다. Figma의 최대 화자 수 정책은 미확정이다.

## 작업 복원과 저장

- 앱은 업로드/렌더 요청 키, 분석/렌더 작업 ID, 적용 프로필 버전, 캐릭터 배정을 영속 저장한다.
- 네트워크 중단이나 WorkManager 재시작은 기존 ID를 이어받는다. 같은 요청 키의 재전송은 서버에서 새 작업을 중복 생성하지 않는다.
- 명시적인 실패 재시도는 기존 원본·모델 설정으로 서버 재시도 작업을 만든다. 서버 보관기간이 지난 결과를 사용자가 재시도하면 기기에 남은 원음으로 다시 업로드한다.
- 기기 결과 이름에 렌더 작업 ID를 포함해 이미 게시된 영상을 덮어쓰지 않는다. 파일 다운로드와 메타데이터 게시에 임시 파일·원자적 교체를 사용한다.
- 기존 서버 정책: 원음 기본 24시간, 결과 기본 30일. 서버 재시도 가능 기간과 기기에 보관한 원음 수명은 다르다.
- 분석용 PCM·분리 임시 파일은 현재 `D:\MOMO_Development\lab-temp\app-episodes`에서 작업하며 정상 종료/오류 처리 후 정리한다. 프로세스 강제 종료로 남은 외부 임시 디렉터리는 별도 관리 대상이다.
- 서버의 계정/작업 DB·업로드 원음·완성 산출물은 기존 `server/data` 아래 유지한다. 기기 녹음과 영상 보관 위치도 유지한다.

## 서버 설정과 실행

`server/episode-profile.example.json`을 참고해 `server/data/episode-profile.json`을 작성하면 **다음 분석 요청**부터 적용한다. 프로필 경로는 `MOMO_EPISODE_CONFIG_FILE`로 지정할 수도 있다. 이미 접수된 작업의 설정은 바뀌지 않는다. `threshold`가 웃음 감도이며, 알 수 없는 설정 키는 오류로 처리한다.

Claude를 사용하려면 `speaker_review.mode=claude`, 유효한 `speaker_review.model`을 지정하고 `ANTHROPIC_API_KEY`를 서버 환경 또는 `server/.env`에 설정한다. OpenAI 실험 모델은 같은 방식으로 `OPENAI_API_KEY`를 설정한다. 키는 앱·프로필 파일·작업 DB에 저장하지 않는다. 현재 검증은 로컬 모델로 진행하며 유료 API 호출은 포함하지 않는다.

현재 PC에서 프로젝트 루트 기준:

```powershell
.\server\.venv\Scripts\python.exe server/manage.py start --port 8765 --device cuda --models D:\MOMO_Development\models --data-dir C:\Users\whdrm\AndroidStudioProjects\HD_project\server\data --work-dir D:\MOMO_Development\lab-temp\app-episodes --cuda-root D:\MOMO_Development\cuda-runtime
.\server\.venv\Scripts\python.exe server/manage.py status
```

현재 C: 드라이브가 부족해 새 `--work-dir` 옵션으로 임시 작업을 D:에 분리했다. 원본/결과의 영속 저장소 공간도 별도로 확보해야 한다. 워커는 기존 GPU 모델을 해제한 뒤 `.lab-venv`의 웹 엔진을 별도 프로세스로 실행해 GPU 모델 중복 상주를 피한다. 워커 처리 제한은 새 경로에서 24시간이며 앱은 8분 단위 WorkManager 실행을 이어간다. 모델/OS/드라이버에 따라 실제 시간은 달라진다.

새 서버 설치에는 기존 추론 의존성과 `server/audio-lab-requirements.txt`, 모델 캐시·FFmpeg·한글 폰트·디자이너 기본 소스가 필요하다. 기존 Docker/HTTPS 배포 구성은 이번 로컬 통합 검증 대상이 아니다. 특히 기존 Nginx의 85MB 업로드 제한, 컨테이너의 웹 엔진 의존성·소스·폰트·모델 캐시 준비를 그대로 두고 새 경로의 공개 배포가 완료됐다고 판단하면 안 된다.

## 검증 기록

실제 차량, 장시간 원음, 새 Docker 배포, 외부 유료 모델은 미검증이다. 아래 화면 크기 검사는 네이티브 뷰의 지정 크기 측정·배치 검사이며 FormFactorConsole의 실제 12개 가상 디스플레이 실행과 다르다.

| --- | --- |
| Android debug·androidTest APK 빌드, 단위 테스트, lint | 통과. 단위 테스트 49개, 실패 0. APK를 기존 앱 위에 업데이트 설치. |
| 서버 회귀 검사 | 145개 통과. 인증·작업 소유권·요청 중복·프로필 고정·재시도·만료·기존 하이라이트·독립 트랙·대사 중복·웃음·시선·긴 녹음 관련 검사. AI 추론을 대체한 계약 테스트와 실제 추론을 구분함. |
| 최종 임시 경로/프로필/서버 재시작 검사 | 추가 11개 통과. 임시 경로 변경 후 기존 데이터·계정 보존. |

| 실제 원음으로 앱→GPU 서버→앱 | 51.28초 테스트 대화에서 25.98초·24.94초 영상 2개 생성. 분석 작업 119.550초, 렌더 작업 30.231초. 앱 작업 취소/재시작 후 동일 분석 ID 유지, 원음 SHA-256 유지, MP4·포스터·자막 검증 및 완료 후 재요청 중복 없음. 계측 2개 테스트 전체 152.212초. |

최종 화면 크기 검사: **12개 가로/세로 프리셋 × 홈·캐릭터·보관함·설정 4화면 = 48개 배치, 잘림/가로 이탈 0건**, 계측 테스트 52.123초. 처음에는 좁은 12.9인치/Waterfall 보관함에서 긴 서버 오류 문구 잘림 2건이 검출되어 카드 2줄 요약과 상세 화면의 가변 높이로 수정한 뒤 재검증했다.

산출물: `build/reports/web-episodes/`의 실제 홈·재생·자막 캡처와 작업 JSON, `build/reports/console-connection/web-episodes-*.txt`, `server/data/web-episodes-tests.txt`. 실제 테스트 영상 2개와 테스트 원음은 앱 보관함에 남겼다. 실제 대사·화자별 정답 대조에 의한 정량 품질 검증은 하지 않았으므로 STT·웃음 화자 매칭 오류가 모두 해결됐다고 보고하지 않는다.

적용 규칙: SIZE-01~06(기존 창 기준 반응형 배치 유지), STATE-01~04(작업 영속화/복원), DRIVE-02(기존 재생 제한 경로 유지), PERF-01(분석·렌더 서버 이관), API-01(권한/SDK 추가 없음). 이 항목은 구현 대응이며 실차 동작 통과 기록과 다르다.

Android: minSdk 28, compile/target 37, AGP 9.4.1, Pleos Vehicle 2.3.2, WorkManager 2.10.3, Media3 1.9.0. 에뮬레이터: Pleos Connect 2.1.0 / API 34, 사용자 10. 실제 앱 창은 기존 1682×1210dp 가로 환경이며 공식 1700×1184dp 프리셋과 동일하다고 간주하지 않는다.

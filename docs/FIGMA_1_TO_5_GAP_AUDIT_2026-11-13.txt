0. 비교 기준과 판정 방법
============================================================
현재 연결된 Figma 파일의 다음 5개 페이지를 읽고, 현재 작업 폴더의 코드를 대조했다.
파일: https://www.figma.com/design/Y5hqYUqZsj6gQu1QyixBYv/Untitled
  01. 디자인 시스템: 144:422
  02. 기능명세: 721:7362 / 현재 native spec 721:7363
  03. M.S / I.A: 440:1405
  04. UI: 616:3027
  05. 제출 자료: 1042:1935

코드 기준: HEAD 552e116 이후 현재 작업 폴더에 반영된 수정까지 포함.
이전 검토 문서의 오래된 미구현 목록을 그대로 재사용하지 않았다.
앱 코드, Figma, 녹음·영상·분석 자료는 변경하지 않았다. 이번에 추가한 것은 검토 기록이다.

판정:
  [미구현] 요구에 해당하는 현재 실행 경로가 없다.
  [부분 구현/불일치] 기능은 있지만 명세의 일부 동작·배치와 다르다.
  [검증 필요] 구현은 있으나 실제 품질·예외·차량 동작을 완료로 판정할 근거가 부족하다.
  [정책 정리] Figma의 미정 항목 또는 이후 사용자 결정과 기존 명세가 충돌한다.
  [범위 제외] 사용자가 이후 명시적으로 제거했으므로 개발 누락으로 세지 않는다.

이번 검토에서 확인한 범위:
  - 5개 페이지의 현재 텍스트·명세·구조, FN-01~20 전 항목.
  - 현재 앱의 화면 라우팅, 녹음 저장/복구, 제작 작업, 화자/자막,
    프로필, 권한, 재생 및 debug/release 차량 신호 코드를 대조.
  - Figma의 홈·녹음·저장·제작 주요 화면 이미지 확인.
  - 과거 실행 검증 자료를 참고하되 이번에 다시 실행한 검사로 표현하지 않음.
  - 112개 차량 상태의 넓은/좁은 모든 화면을 새 APK로 하나씩 재촬영한
    전체 픽셀 비교는 하지 않았다. 모든 상태의 시각 일치를 보증하는 보고서가 아니다.

핵심 결론:
녹음 → 기기 내 분석 → 하이라이트/영상 제작 → 보관함 → 재생은 구현돼 있다.
하지만 Figma 전체 구현 완료 상태는 아니다. 우선 보완해야 할 것은 다음이다.
  1) release 빌드의 시동 OFF 신호 연결
  2) 같은 원본 녹음의 여러 하이라이트 사이에서 동일 화자의 캐릭터 유지
  3) 정상 저장 후 재실행 및 저장 재시도 실패의 정확한 분기
  4) 최초 권한 안내, 주행/정차/Gleo 복귀, 프로필 예외 화면
  5) 저장·제작 화면의 단계 표시와 공통 디자인 수치 적용
  6) 자막/화자 정확도 검증, 현재 구조에 맞는 제출 자료 정리

1. 01 디자인 시스템 기준
============================================================

V01. 공통 하단 버튼 위치 [불일치]
Figma: 1184 높이 설계에서 버튼 y=936, 높이=88, 아래 여백=160.
근거: 1012:9993, native spec의 하단 액션 규칙.
현재: 저장 결과, 제작 진행, 이름/최초 프로필, 마이크 권한 안내는
      height-160을 버튼의 시작 y로 사용한다.
      높이 1184일 때 y=1024, 버튼 하단=1112, 아래 여백=72가 된다.
      Figma보다 88 아래에 배치된다.
범위: 녹음/목소리 확인 등 height-248을 사용하는 화면은 이 문제와 구분한다.
보완: 공통 하단 액션 계산을 통일하고 낮은 창에서는 스크롤과 함께 검증.
코드: TikiActivity.kt:443,579,686,747.
주의: 이 수치는 Figma 기준 화면과의 비교이며 Pleos 공식 버튼 좌표가 아니다.

V02. 이름 입력 컴포넌트의 크기·글자·모서리 [불일치]
Figma: 최초 이름 입력 넓은 800×88 / 좁은 640×88, R16, 본문 24/32.
현재: 너비 min(720,w-64), 높이112, R24, 글자32.
영향: 실제 동작은 하지만 디자인 시스템의 입력칸과 눈에 띄게 다르다.
보완: 최초 프로필/이름 화면의 입력 컴포넌트를 명세의 크기와 스타일에 맞춤.

V03. 저장/분석/영상 제작별 이미지와 크기 [부분 구현]
Figma: 저장 완료(손인사+체크), 대화 분석(돋보기), 영상 제작(클래퍼)을

보완: 실제 처리 단계와 결과 상태별로 Figma 오브제를 연결.
코드: TikiActivity.kt:440,576.
Figma: 1019:1937,1134:1949.

V04. 공통 타이포그래피·세부 간격 [부분 적용]
현재: Asta Sans/Jua, 주요 색상, 사이드 메뉴, 8종 캐릭터 등은 이미 적용.
      다만 글자 크기를 화면별로 직접 지정하고 공통 TextView는 Figma의
      24/32,36/48 같은 행간 규칙을 명시적으로 적용하지 않는다.
      V02처럼 수치가 다른 컴포넌트도 있다.
보완: 디자인 시스템의 글자 크기/행간/입력/목록/버튼을 재사용 규칙으로
      묶고 각 기준 화면과 대조. 모든 텍스트가 틀렸다는 판정은 아니다.
코드: TikiViews.kt:71-79, TikiActivity.kt의 화면별 text() 호출.

이미 적용된 디자인 요소 — 누락으로 세지 않음:
  - 최신 서비스 시작 문구, 기본 청록 캐릭터, 주요 로고/폰트/메뉴.
  - 고정 캐릭터 8종, 7개 후보, 순환 탐색, 확정 저장.
  - 1칸 350ms / 다중 이동 240ms 단위 캐릭터 회전 코드.
  - 에피소드별 썸네일 10종의 동일 파일 연결.
  - 영상 표시 영역 16:9.
  - 홈 썸네일 약 220×132/176×106은 Figma 홈 자체의 명시된 배치다.
    썸네일 원본이 1920×1080이라는 이유만으로 이 홈 배치를 오류로 세지 않았다.

2. 02 기능명세 FN-01~20 전 항목

FN-01 시작과 권한 — 부분 구현

FN-04 캐릭터 선택 — 기본 기능 구현, 새 버전 적용 정책 차이
  8종/7후보, 순환, 직접 탐색, 확정만 저장, 취소 시 원래 값,

  기존 원음으로 새 버전 제작 시 이전 캐릭터 재사용은 A04 참조.

FN-07 녹음 중 제어 — 부분 구현

기능의 중요한 실제 처리 차이
------------------------------------------------------------

A01. 최초 권한 안내와 선택 위치 기능 [미구현/부분 구현]
Figma: A-00 → A-01 서비스 권한 안내 → A-02 마이크 → A-03 위치(선택)
       → O-02 이름/캐릭터. 위치 거부해도 녹음 가능.
현재: welcome의 시작 버튼은 바로 profile로 이동.
      마이크는 첫 녹음/목소리 확인 시 요청. 거부 안내와 앱 설정 이동은 있음.
      현재 manifest/앱 경로에는 선택 위치 권한/위치 수집 연결이 없음.
영향: 피그마 최초 사용 순서, R-05 위치 누락 상태를 재현할 수 없음.
보완: 현재 범위에 위치를 유지할지 정리한 뒤 필요하다면 연결.
      사용자가 제거한 날씨와 위치는 별개다. 날씨 기능 복원을 요구하는 항목이 아니다.
코드: TikiActivity.kt:96,312,324,400,742; app/src/main/AndroidManifest.xml.
Figma: FN-01, FN-07; M.S/I.A 721:6946.

A02. 실제 배포 빌드의 시동 OFF 자동 종료 [미구현]
Figma: 시동 OFF를 정상 종료 계기로 받아 파일 마감/검증 후 자동 제작 또는 보관.
현재 debug: 에뮬레이터에 한해 http://127.0.0.1:8088/vehicle/power-system을
            읽어 OFF를 RecordingService 종료로 전달하는 어댑터가 있음.
현재 release: RecordingPowerSignals.watch()가 아무 리스너도 등록하지 않는
              AutoCloseable을 반환. OFF 이벤트가 들어오는 경로가 없음.
영향: 에뮬레이터용 브리지를 사용하는 debug 시연과 release/실차 동작이 다름.

6. 확정 개발 누락과 구분해야 할 정책·품질 항목
============================================================

P01. 부분 복구 원음의 수동 영상 제작
현재: 자동 제작은 막지만 저장 결과에서 직접 제작 가능하다고 안내하고
      보관함/원음 경로에서 수동 제작할 수 있음.
Figma: 부분 복구 자동 제작 제외는 확정, 수동 제작 허용 세부는 결정/검증 대상.
판정: 자동 제작 제외는 구현. 수동 제작은 확정 규칙 위반으로 단정하지 말고
      허용 조건·사용자 안내·실패 처리를 확정해야 함.

P02. 보관과 삭제 안내
현재 개인정보 화면: '직접 삭제하거나 앱 데이터를 삭제할 때까지 보관'.
현재 Tiki 화면: 원음/영상/목소리 참조를 골라 삭제하는 통합 UI는 없음.
시스템 앱 데이터 삭제는 가능하지만 특정 항목만 지우는 경로와 다름.
Figma FN-18은 일괄 삭제 권고 보류, 휴대폰 삭제는 범위 제외 상태.
판정: 일괄 삭제를 임의 필수 개발로 확정하지 않음. 현재 제공하는 삭제 방법에
      맞게 안내하고 원음·분석·영상·목소리 참조의 삭제 연동 정책을 정리할 필요.
코드: TikiActivity.kt:734-740.

P03. 인원 상한과 여정/배경 연결
현재: 등장인원 자동1~4명, 미검출 시2개 캐릭터 대체,
      기본 배경은 city-road-loop.mp4로 고정.
Figma: 고정8종은 선택 가능한 캐릭터의 수이고, 8명이 반드시 동시에 등장해야
       한다는 요구가 아님. 최대 화자 수/초과 처리 정책은 확인 필요로 남아 있음.
       여정·배경 연결도 적용 범위/입력 출처/규칙 확인 대상으로 표시.
판정: '8명 지원 미구현'이라고 세지 않음. 4명 초과 시 동작과 실제 여정 기반
      배경을 제공할지의 범위를 명확하게 기록할 항목.
코드: ProductionSettings.kt:13,22; LocalDiarization.kt:67; TikiScene.kt:17.

Q01. 음성 품질 [검증 필요]
STT 인식 누락, 짧은 발화/동시 발화의 화자 구분, 등록한 내 목소리 매칭,
여러 하이라이트 간 같은 사람 유지, 웃음 검출과 실제 웃은 사람의 신원을
구분하여 평가해야 함.
웃음을 캐릭터에 배정하는 로직은 웃음 주인의 신원을 검증한 결과가 아니다.
최근 샘플에서 웃음 반영/2캐릭터/진단 수치는 검사했지만 일반 정확도의 증거는 아님.

Q02. 긴 녹음·저장 실패·전원 중단 [검증 필요]
2~3시간 실제 입력, 저장 공간 부족, 파일 손상, 갑작스러운 프로세스/전원 종료,
권한 철회, 여러 작업 복원까지 같은 실행 조건으로 종합 검증한 근거가 필요.
영속 기록/WorkManager 코드가 있다는 사실만으로 모든 상황을 통과했다고 하지 않음.

Q03. 전체 창 크기·상태 전환 [검증 필요]
코드에는 실제 할당 창 크기 기반 재배치/스크롤 및 상태 저장이 있음.
기존 12개 dp 프리셋 뷰 측정 검사는 해당 화면의 측정/배치 근거다.
FormFactorConsole 전체 프리셋, 시스템 패널/키보드, 주행 제한 진입/해제,
백그라운드 복귀/앱 재생성까지 모두 검증했다는 의미는 아님.

Q04. 성능·실차 [검증 필요]
기존 20초 원음의 재제작 기록: 약69.793초. 별도 웃음 분석 기록:1.486초.

# 사용자 관리와 목소리 기반 캐릭터 매칭

## 앱에서 사용

1. 홈 오른쪽 위 **사용자 관리 → 사용자 추가**를 엽니다.
2. 이름과 제공된 캐릭터 1 또는 2를 선택합니다. 이름·캐릭터만 먼저 저장해도 됩니다.
3. **저장된 녹음에서 목소리 등록**에서 본인이 말한 녹음을 선택하고 전송·목소리 이용 안내에 동의합니다.
4. 분석된 화자를 **미리 듣기**로 확인하고 **S1/S2… 목소리 선택 → 저장**합니다. 해당 인물의 겹치지 않는 깨끗한 발화가 최소 6초 필요합니다. 조용한 곳에서 혼자 10~20초 말한 녹음을 권장합니다.
5. 이후 **저장된 기록 → 영상 만들기**를 사용하면 등록 목소리와 비교하여 이름·캐릭터를 적용합니다. 등록되지 않았거나 불확실한 화자는 **새로운 사람 N / 캐릭터 1**입니다.

등록된 A·B·C 중 다음 녹음에 B·A·D가 나타나면 화자 번호와 별개로 B와 A의 캐릭터를 찾고 D는 기본 캐릭터로 표시합니다. 이번 녹음에서 감지되지 않은 C는 등장하지 않습니다. 두 화자가 같은 등록 인물과 매칭되면 둘 다 기본 캐릭터로 남겨 잘못된 자동 배정을 줄입니다.

**수정 / 목소리 다시 등록**으로 이름·캐릭터·목소리를 바꾸거나 등록 목소리를 해제할 수 있습니다. 변경 내용은 **저장**할 때 반영합니다. 삭제는 등록 인물 정보만 지우며 원본 녹음·분석 캐시·기존 완성 영상은 유지합니다. 이미 만든 MP4를 바꾸려면 다시 생성합니다.

## 처리와 저장

- 녹음 종료 후 서버에서 Nemotron 화자 분리와 별도로 SpeechBrain ECAPA-TDNN 192차원 임베딩을 추출합니다. 겹친 말·웃음·불명확한 화자·너무 짧은 구간을 제외하고 화자별 최대 30초를 사용합니다. 서로 일관되지 않는 샘플은 등록 후보에서 제외합니다.
- 서버 결과에는 `voice_model_id`, `speaker_signatures`가 추가됩니다. 특징은 기존 계정별 인증·소유권 검사를 거친 분석 결과로만 전달됩니다. 인물 이름·캐릭터 선택은 서버에 전송하지 않습니다.
- 앱은 UUID로 인물을 식별합니다. 이름과 캐릭터 ID, 등록 임베딩, 모델 ID, 유효 발화 시간, 등록 시각·원본 제목을 Android Keystore AES-GCM + AtomicFile로 저장합니다. 별도 등록용 음성 파일을 복사하지 않습니다. 원본 녹음을 삭제해도 등록 임베딩은 유지됩니다.
- 인물 파일: `context.noBackupFilesDir/momo-people/profiles.enc`. 현재 에뮬레이터 사용자 10에서는 `/data/user/10/com.example.hd_project/no_backup/momo-people/profiles.enc`입니다. Windows의 일반 폴더는 아니며 앱 내부 저장소입니다.
- 기존 녹음은 `no_backup/recordings/`, 목소리 특징이 포함된 분석 캐시는 `no_backup/momo-projects/`, 완성 영상은 `no_backup/momo-videos/`입니다. 분석 캐시는 앱 전용 저장소로 보호되지만 인물 파일과 같은 추가 암호화를 적용하지 않습니다. 앱 데이터는 백업 대상에서 제외됩니다.
- 서버 원본은 분석 종료 후 24시간, 특징을 포함한 분석 결과는 30일 보관하는 기존 정책을 따릅니다. 인물 삭제가 원본·분석 결과 삭제를 의미하지 않습니다. 완성 MP4에는 표시 이름과 원본 목소리가 포함됩니다.
- 인물 목록의 해시를 MP4 메타데이터에 넣어 인물 수정·삭제 후 예전 영상을 최신 구성의 결과로 재사용하지 않습니다. 예전 분석에 목소리 특징이 없으면 동의 후 녹음을 재분석합니다.

## 모델과 운영

- 모델: [SpeechBrain spkrec-ecapa-voxceleb](https://huggingface.co/speechbrain/spkrec-ecapa-voxceleb), Apache-2.0. 고정 revision, 83,316,686바이트 가중치의 SHA-256은 `contracts/voice-model-lock.json`에 있습니다.
- 서버의 고정 PyTorch CPU 2.5.1 / torchaudio 2.5.1 / SpeechBrain 1.0.3을 사용합니다. FFmpeg에서 디코딩한 PCM을 직접 전달하므로 torchaudio 파일 로더를 사용하지 않습니다. 원격 YAML 실행이나 실행 중 모델 다운로드는 하지 않습니다.
- 기존 환경 업데이트: `uv sync --frozen --extra inference`, 이어서 서버 디렉터리에서 `python -m momo.prepare_voice_model`을 실행하고 API와 worker를 재시작합니다. 전체 `momo.prepare_models`에도 음성 모델 준비가 포함됩니다.
- 현재 PC의 모델은 `D:\MOMO_Development\models\voice`에 있으며 `server/data/models` junction을 통해 사용합니다. APK에 모델을 넣지 않습니다.
- 모델 ID가 다른 기존 등록 음성은 비교하지 않습니다. 모델 변경 시 해당 인물의 목소리를 다시 등록합니다.

## 범위와 검증

실시간 탑승자 식별이나 인증 기능이 아닙니다. 녹음 후 영상 제작 시 적용합니다. 현재 인물은 20명까지 등록하며 영상에는 처음 감지된 4명까지 표시합니다. 나머지 원본 음성·자막은 유지합니다. 좌석 배치는 발화 순서이며 실제 탑승 좌석 추정이 아닙니다. 캐릭터 종류는 제공된 두 세트를 사용하므로 여러 인물이 같은 외형을 선택할 수 있습니다.

자동 매칭 기준은 코사인 유사도 0.65 이상, 2위와 차이 0.08 이상입니다. 보수적인 초기값이며 한국어 실차 녹음으로 보정된 수치나 정확도 보장이 아닙니다. 자동차 소음, 마이크 변화, 짧은 말, 비슷한 목소리, 겹친 말, 화자 분리 오류로 미매칭 또는 오매칭이 생길 수 있습니다. 등록 음성은 실제 대화 조건에 맞춰 재녹음할 수 있습니다.

테스트는 ABC→BAD 순서 변경·새 화자, 낮은 점수·근접 후보·중복 배정·모델 버전 변경·짧은 음성, 인물 수정·삭제, 암호화 파일 재열기·변조 탐지, 앱 편집 상태 복원, 합성 한국어 음성 등록 및 실제 MP4 생성 경로를 다룹니다. `tools/verify-voice-model.py`는 공식 공개 샘플 두 개로 실제 모델 입출력을 점검하며, 같은 클립의 볼륨 변화 시험을 실차나 다른 세션 정확도 평가로 간주하지 않습니다. 실제 사용자의 녹음을 테스트용으로 서버에 추가 업로드하지 않습니다.

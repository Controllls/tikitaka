티키타카 기기 단독 제작 전환 및 휴대폰 기능 제거
작성: 2026-11-13

1. 변경 범위
- 현재 차량 앱의 녹음 → 음성/웃음/화자 분석 → 하이라이트 선택 → 영상 합성·저장 경로를 기기 안에서 처리한다.
- 서버의 event-context-rules-v1 하이라이트 선택을 LocalHighlightPlanner.kt로 이식했다. GPT/Claude/Qwen을 앱에 추가한 변경은 아니다.
- 웃음 점수 우선, 같은 점수이면 원본 시각 순서, 앞뒤 문맥 포함, 중복 구간 조정, 웃음이 없으면 대화 발췌의 기존 동작을 유지한다.
- 클립 기본 최대 40초, 설정 최대 120초, 앱 최대 3개를 유지한다. 12시간 입력 검증 한도는 구현상의 상한이며 실제 처리 성능 보장이 아니다.
- 원음·전사문·웃음 점수·화자 정보·완성 영상을 서버로 보내지 않는다. 현재 제작에는 서버 주소·설치 인증·토큰이 필요하지 않다.
- PC 웹 실험 도구와 이전 분석 API는 별도 실험용으로 남긴다. 현재 앱의 MetadataEpisodes/EpisodeWork는 호출하지 않는다.

2. 휴대폰 기능 제거
- 설정의 휴대폰 연결, 코드 발급·승인·해제, 상태 조회·폴링을 제거했다.
- PhoneSync/PhoneSyncWorker 및 완성 영상·자막 업로드를 제거했다.
- Application 시작 시 이전 버전의 일회성/주기 동기화 예약을 취소하고 연결 설정을 정리한다. 마이그레이션 완료 후 반복 실행해도 안전하다.
- 이전 화면 상태가 phone이면 설정 화면으로 복귀한다.
- 서버의 /v1/phone/*, /phone/api/*, /phone/ 화면과 전용 웹 리소스를 제거했다. 자막을 합친 휴대폰 공유 파일 제작 경로도 제거했다.
- DB 마이그레이션 이력과 이미 저장된 서버 자료는 삭제하지 않았다. 기존 휴대폰 테이블은 자동 마이그레이션 삭제 대상으로 삼지 않으며 조회·다운로드 경로는 제공하지 않는다.
- 사용자의 제거 요청에 따라 기존 Figma 휴대폰 화면은 지원 범위에서 제외한다. Figma 원본·과거 검증 문서는 이력으로 보존한다.

3. 기존 자료와 작업 복구
- 기존 plan.json, 길이별 계획, 원음, 분석 체크포인트, 완성 MP4 및 자막·진단 결과를 보존한다.
- 새 계획은 버전이 붙은 로컬 해시를 사용한다. 이미 저장된 계획의 ID는 변경하지 않아 완료 영상의 재사용을 유지한다.
- 새 버전 제작은 별도 출력으로 저장한다. 저장된 영상을 덮어쓰지 않는다.
- 이전 자동 하이라이트 서버 대기 작업은 기기 작업으로 전환한다. 이미 완료한 기기 작업은 다시 만들지 않는다.
- 기기 저장 공간·모델·코덱 오류를 서버 접속 대기로 오인해 반복 재시도하지 않는다. 중단된 분석의 체크포인트와 원음은 유지한다.
- 녹음 동의, 개인정보 안내, 제작 진행/대기 문구를 실제 기기 처리 방식에 맞췄다.

4. 검증 결과
- Android debug 앱/계측 APK 빌드 성공. JVM 테스트 58개 통과.
- 기존 Python 서버에서 얻은 7개 입력/결과와 Kotlin 구간 선택 결과가 일치한다. 동점·구간 중복·유니코드 제목·대화 대체·짧은 파일·120초·부분 인식 사례를 포함한다.
- 유효하지 않은 시간·점수·중복 구간·입력 개수·알 수 없는 필드는 거부한다. JSON 순서/공백이 달라도 계획 ID는 같다.
- 서버 전체 테스트 293개 통과. 기존 데이터베이스 마이그레이션 유지 및 제거한 휴대폰 경로 15개에 대한 404 회귀 검사를 포함한다.
- 실제 실행 서버를 갱신한 뒤 /phone/, /v1/phone/state, /phone/api/episodes의 404와 /health/live의 200을 확인했다. PC 분석 worker도 ready 상태로 복구했다.
- 백엔드 주소를 http://127.0.0.1:1/로 설정한 debug 앱에서 실제 웃음 샘플 → 기기 분석 → 하이라이트 → 오디오 포함 MP4 → 보관함 저장 → 동일 영상 재사용 → 별도 버전 재제작을 통과했다. 원음/기존 MP4 해시 보존, 포스터·자막 파일·진단 데이터·4인 장면 구성을 검사했다.
- 이 샘플의 첫 영상 완료는 21,363ms였다. 짧은 웃음 샘플 한 건의 측정이며 2~3시간 대화 처리 속도로 환산할 수 없다. 해당 샘플의 STT 상태는 unavailable이며 웃음 이벤트로 제작했다.
- 변경 관련 계측 테스트 8개 최종 통과: 기기 영상 제작·원음 업로드 차단·예약 폐기·기존 서버 큐 전환·설정/개인정보 배치·동의 배치·동의 취소/재생성·실제 모델/SDK 대조. 동의 취소 검사의 이전 서버 전송 문구 기대값을 새 안내로 갱신한 뒤 재실행했다.
- 기존 휴대폰의 두 예약 작업이 CANCELLED가 되고 연결 설정만 정리되는 계측 검사 통과. 이전 서버 큐가 기존 완료 영상 상태를 보존하고 다시 생성하지 않는 것도 확인했다.
- 설정·개인정보 24개 및 녹음 동의 두 모드 24개, 총 48개 정적 화면 검사에서 잘림 0건. Standard 17/14.6/12.9, Wide 기본/확장, Waterfall의 가로·세로 프리셋이다.
- Lint 오류 0건, 경고 86건. 경고가 없는 프로젝트로 보고하지 않는다.
- 작업 전 존재한 원음·영상·분석·하이라이트 파일 227개를 SHA-256으로 대조해 227개 모두 동일함을 확인했다.
- 상세 로컬 산출물: build/reports/local-only/ 아래 e2e-unreachable-backend.json, preservation.json, layouts.json, consent-layouts.json, retired-routes.json 및 화면 PNG.

5. 개발 규칙 및 환경
- 기능/화면: 기기 하이라이트 계획, 작업 복구, 휴대폰 기능 폐기, 설정·개인정보·녹음 동의.
- 프로젝트 구현 규칙: SIZE-01~06에 따라 기존 실제 창 기반 배치를 유지하고 12개 크기 프리셋으로 변경 화면을 정적 검사했다. STATE-01/02/04의 상태 유지·작업 복구·불필요한 폴링 제거를 적용했다.
- 기존 DRIVE-01/02의 CarUxRestrictions 기반 주행 중 영상 제한은 변경하지 않았다. 이번 변경으로 신규 차량 권한을 추가하지 않았다.
- SDK/의존성: minSdk 28, compileSdk/targetSdk 37, Vehicle 2.3.2, SpeechToText 3.3.1, LiteRT 1.4.2, Media3 1.9.0, WorkManager 2.10.3. 버전 변경 없음.
- 실행 환경: Windows, Pleos_Connect_v2.1.0, Android 14/API 34, x86_64, emulator-5554, Android 사용자 10. 기존 앱에 업데이트 설치했으며 앱 데이터 초기화/제거는 하지 않았다.
- 대상 가정: 한국어 차량 내 대화 기록·엔터테인먼트 앱. 마켓 카테고리/실차 배포 지역의 최종 정책 확정을 대신하지 않는다.
- 12개 크기는 공식 표의 dp 설계 프리셋이다. 정적 View 크기 검사를 실차/모든 폼 팩터의 실제 창 전환 검증으로 표현하지 않는다.

6. 남은 제한·미검증
- 실제 한국어 합성 음성 대조에서 안전벨트·드라이브 문장을 수신했다(자막 1개). 무음은 웃음 0개, 웃음 샘플은 웃음 1개로 구분했다. 세 샘플 모두 STT 완료 상태는 false/TIMEOUT이었다. Pleos STT에서 한국어 문장을 받더라도 파일 입력 완료 콜백이 늦어 partial/TIMEOUT이 되는 기존 문제가 있다. 이번 변경은 STT/웃음/화자 모델의 정확도를 개선한 작업이 아니다.
- PC 웹의 Whisper·Qwen·Claude·GPU 소스 분리 모델 전체를 Android로 옮긴 것이 아니다. 현재 앱에 이미 있는 기기 모델과 새 로컬 구간 선택을 사용한다.
- 실차, 2~3시간 연속 입력 처리 시간·메모리·발열, 모든 실제 폼 팩터의 시스템 패널/키보드/회전, 주행 제한 전환의 전체 회귀 검증은 미실시다.
- 공식 반응 시간/실차 성능 기준 통과나 공모전·마켓 정책 승인을 이 구현 결과만으로 단정하지 않는다. 차량 마이크 원음의 별도 보관 허용 여부는 앞선 정책 확인 필요 항목으로 남긴다.

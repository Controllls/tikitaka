녹음 API·저장·재생·Pleos STT 에뮬레이터 계측 검증
검증일: 2026-11-13 (Asia/Seoul)
대상: 현재 설치된 com.example.hd_project 디버그 앱 / Pleos 에뮬레이터

결론
- Android 기본 MediaRecorder로 에뮬레이터 마이크 입력을 녹음하고, 내부 저장소에 저장하고, 앱의 실제 재생 화면에서 출력하는 경로는 확인했다.
- 공식 Pleos STT에 녹음 파일의 PCM을 보내면 한국어가 인식된다. 그러나 현재 앱의 완료 대기 로직에서 TIMEOUT이 발생했다. 전체 정상으로 판정하지 않는다.
- MediaRecorder와 공식 STT의 request()를 동시에 실행하면, 두 가지 시작 순서 모두에서 STT 서비스 입력이 silenced=true로 표시되었다. 이 환경에서 두 API의 동시 마이크 사용은 정상으로 판정하지 않는다.
- 현재 제품 경로는 녹음 종료 → 파일 디코딩 → sendAudio() 방식이다. 동시 request() 시험은 호환성 확인을 위한 추가 시험이며, 현재 제품 동작과 구분한다.

관련 권한 (현재 Android 사용자 10에서 모두 granted=true):
  android.permission.RECORD_AUDIO — 마이크 입력
  android.permission.FOREGROUND_SERVICE — 포그라운드 서비스
  android.permission.FOREGROUND_SERVICE_MICROPHONE — 마이크 유형 서비스
  pleos.car.permission.STT_SERVICE — Pleos 공식 STT
  POST_NOTIFICATIONS도 허용되어 있으나, 이는 알림 표시 권한이다.
  앱 내부 저장소 저장에 별도의 외부 저장소 권한을 사용하지 않는다.

4. 파일 입력 공식 STT — 인식 성공 / 앱 완료 판정 실패

  위에서 직접 녹음한 파일로 현재 PleosLocalStt.recognize()를 실행했다.
  '오늘은 함께 드라이브를 하기로 했어요', '안전벨트를 확인하고 천천히 출발해요' 등이 인식되었다.
  결과: complete=false, error=TIMEOUT, 소요시간 39,039 ms
  통합 시험의 정상 완료 assertion은 실패했다. 전체 시험 성공으로 보고하지 않는다.

  원인 확인 시험: file-events-01
  같은 파일을 공식 SDK에 전달하면서 콜백의 도착 시간을 기록했다.
  completeAudioSend() 전 onEndedRecognition: 6회
  completeAudioSend() 후 onEndedRecognition: 0회
  마지막 종료 콜백은 completeAudioSend()보다 6,932 ms 먼저 도착했다.

  현재 PleosLocalStt.kt:31~32는 inputFinished=true 이후에 도착한 종료 콜백만 완료로 처리한다.
  따라서 파일 입력 중 이미 끝난 문장들의 종료 이벤트가 완료 판정에서 무시된다.
  입력이 끝난 뒤 새로운 종료 이벤트가 없으면 8초 대기 후 TIMEOUT으로 처리된다.
  이 시험은 '음성을 인식하지 못함'이 아니라 '인식 결과를 받고도 전체 완료 판정을 못함'이다.
  코드 수정 시 입력 완료와 문장 완료 상태를 함께 다루어야 한다. 첫 문장 종료만으로 전체 파일 분석을 끝내면 안 된다.

5. MediaRecorder와 공식 STT의 동시 마이크 사용

  concurrent-01: MediaRecorder 시작 → 공식 STT request()
  stt-first-01: 공식 STT request() → MediaRecorder 시작
  두 순서 모두:
    우리 앱 MediaRecorder (MIC / 44.1 kHz): silenced=false
    ai.pleos.playground.caas STT 입력 (VOICE_RECOGNITION / 16 kHz): silenced=true

  Android activeRecordingConfigurations 및 dumpsys audio에서 확인했다.
  녹음기는 계속 실행되었지만 STT가 정상 음성 입력을 함께 받는 상태는 아니었다.
  두 동시 시험에는 음성을 주입하지 않았다. 마이크 점유·음소거 상태만 검증했다.
  관찰용 instrumentation 시험의 OK는 동시 음성 인식 성공을 뜻하지 않는다.

  공식 STT 단독 request() 음성 인식은 미검증:
  서비스가 마이크를 열고 onReady를 보내는 것은 확인했지만, 이 경로에 gRPC로 음성을 주입하는 중 에뮬레이터가 연결 종료·정지되어 정상적인 인식 결과를 얻지 못했다.
  이를 STT 자체의 음성 인식 실패로 단정하지 않는다. 이 문제로 에뮬레이터를 재시작했으며 최종 상태는 정상 부팅이다.

6. 변경 사항·보존·최종 상태

  제품 앱 코드 및 주요 SDK 버전은 이번 검증에서 변경하지 않았다.

    tools/verify-recording-stt.py
  auditId를 명시하지 않으면 Android 시험은 건너뛴다. 일반 시험 실행으로 녹음하지 않는다.
  최종 테스트 APK 빌드 성공, Python 문법 검사 성공, auditId 없는 2개 시험의 skip 확인.
  주 앱 APK는 재설치하지 않았다.

  시험 전 해시를 확보한 녹음·메타데이터·기존 animations 파일 61개 모두 해시 일치.
  기존 session-journal.json 바이트 단위 복원 확인.
  기존 shared_prefs 변경은 재부팅에 따른 boarding.session_boot 및 새 시험 녹음의 재생 위치뿐이다.
  최신 영상 폴더 no_backup/momo-videos는 종료 시 50개 파일을 확인했다.
  이 폴더는 사전 해시가 없어 바이트 단위 전후 비교 완료로 표시하지 않는다. 시험은 record_only로 실행했으며 해당 폴더에 쓰거나 삭제하지 않았다.
  시험 녹음 3개 및 해당 메타데이터를 추가했으며 '마이크·STT 검증'으로 표시했다.
  최종 확인에서 앱 녹음 서비스는 실행 중이 아니었고, 앱 화면을 다시 열었다.
  합성 음성 주입은 종료했고, 다음 사용자 녹음을 위해 PC 마이크 사용 설정을 켰다.
  첫 중단 시험 이전 PC 마이크 설정은 기록되지 않아 정확한 원래 설정으로 복원했다고 주장하지 않는다.

7. 공식 문서와 이번 관찰의 구분

  공식 문서: Pleos STT request()는 마이크를 통한 인식을 시작한다.
  https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/start-and-stop
  공식 문서: Pleos STT 사용에는 STT_SERVICE 권한이 필요하다.
  https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/declaring-permissions
  공식 문서: 앱이 가진 오디오를 sendAudio()로 전달하는 입력 방식이 제공된다.
  https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/sending-audio-data
  Android 공식 설명: 동시 오디오 캡처에는 우선순위와 무음 처리 규칙이 있다.
  https://developer.android.com/media/platform/sharing-audio-input

  이번 에뮬레이터에서의 녹음·저장 성공은 공모전이나 실차에서 원본 음성 저장이 허가된다는 근거가 아니다.
  공모전 허용 범위, 실차 권한 승인 및 실제 차량에서의 캡처 가능성은 별도 확인이 필요하다.

8. 개발 규칙서 기준 보고

  변경한 화면과 기능: 제품 UI 변경 없음. 명시적으로 실행하는 검증 도구 추가.
  적용한 규칙: API-01의 실제 API·권한 확인, 6.2의 측정값 기록 규칙, 8.2의 검증/미검증 구분.
  API-01 전체 승인 완료가 아니라 설치 환경의 선언·부여 상태 확인이다.
  사용 SDK: SpeechToText 3.3.1, Vehicle SDK 2.3.2, Android 기본 오디오 API.
  시험한 화면 유형과 방향: 기존 에뮬레이터 오디오 화면만 사용. 폼 팩터·방향별 검증은 하지 않음.
  검증 결과: 녹음 저장·출력 성공, 파일 STT 인식 성공/완료 실패, 동시 마이크의 STT 음소거 관찰.
  성능 측정: 28.096초 녹음의 STT wrapper 실행 39.039초(타임아웃 포함). UI 반응 시간·앱 실행 시간은 측정하지 않음.
  미검증: 실제 사용자 마이크·실차, STT 단독 request()의 전체 인식, 장시간 녹음, 음질 주관 평가, 화자·웃음 정확도, 화면 유형별 UI, 주행 상태 전환, 공모전 및 마켓 승인.

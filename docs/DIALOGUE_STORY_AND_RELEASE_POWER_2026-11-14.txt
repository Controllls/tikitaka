대화 기반 제목·장면 구성 및 release 종료 처리
작성일: 2026-11-14 (KST)

1. 구현 범위

앱 카테고리는 차량 엔터테인먼트, 서비스 지역은 한국어 시연 환경으로 가정했다.
화면 구조는 기존 Figma 적용 UI를 사용한다. 이번 작업은 제작 파이프라인과
녹음 서비스 변경이며, Figma 전체 구현이나 전체 폼 팩터 재검증을 뜻하지 않는다.

대화 기반 제목·장면 구성은 debug/release 공통으로 추가했다.
release에는 공식 AAOS 시동 상태 구독과 OS 종료 통지 처리를 추가했다.
현재 Pleos 에뮬레이터는 시동 상태 속성을 제공하지 않는다. 따라서 release에서
실제 시동 OFF가 정상 수신·저장되는지까지 검증 완료했다고 표시하면 안 된다.

2. 대화 모델과 실제 처리 흐름

녹음 마감 → 기존 기기 STT·웃음 분석 → 기존 규칙 기반 하이라이트 선택
→ 선택 구간의 전사문을 Qwen3로 분석 → 새 제목과 장면 구도 생성
→ 기존 화자 분석 → 디자이너 소스와 원음으로 Media3 MP4 제작 → 보관함 저장.

모델: Qwen3-1.7B-Q4_K_M (llama.cpp b12360, 기기 CPU 추론, 2개 스레드).
모델 파일: 1,282,439,264 bytes, 약 1.3GB. APK에는 포함하지 않는다.
최초 HTTPS 다운로드 후 앱 no_backup/story-models/에 저장하며 SHA-256을 확인한다.
모델 다운로드는 공개 가중치 GET 요청이다. 원음·전사문·제목·장면은 전송하지 않는다.
다운로드 중단 시 Range 요청으로 이어받고, 완료 후 검증·이름 변경한다.
모델 준비에는 약 1.4GB 저장 여유, 추론 시작에는 1.4GB 초과 가용 메모리를 요구한다.
이 수치는 프로젝트의 구현 제한이며 Pleos 공식 최소 사양이 아니다.

전사문은 시간순 최대 6개 그룹, 그룹당 최대 200자로 제한한다.
JSON 문법 제약으로 제목·장소·장면 목록을 생성하고 Kotlin에서 다시 검증한다.
제목은 첫 자막 일부를 그대로 잘라 만드는 방식과 별개로 모델이 생성한다.
대사에 없는 성별·가족관계·직함의 일부 표현은 검증에서 거른다.
장소는 원문에 존재하는 장소 단어만 허용한다. 모델이 만든 '식당' 등 원문에
없는 장소는 제거한다. 실제 차량 위치를 추정하거나 GPS 데이터로 표시하지 않는다.

장면 선택과 렌더러 동작:
  wide: 기존 전체 구도.
  speaker: 음향 분석으로 배정된 발화자 쪽으로 6% 구도 확대.
  reaction: 발화자 이외 캐릭터 쪽으로 6% 구도 확대.
  exchange: 기존 좌우 보기 소스를 사용한 서로 바라보기.
  원문에 확인된 장소가 있으면 영상 첫 3초에 '대화 속 장소'로 표시.

구도 대상은 기존 화자 배정으로 정하며 LLM이 화자를 새로 식별하지 않는다.
불명확하거나 겹친 화자는 전체 구도로 처리한다. 웃음·입 움직임·자막·원음은
기존 음향 분석을 따르고 모델이 수정하지 않는다. 청자 반응은 연출 선택이며
실제 웃음 주인이 누구인지에 대한 새로운 증거가 아니다.

배경·차량·캐릭터는 제공받은 소스를 사용한다. 새로운 배경 이미지나 장소 영상을
생성하는 이미지/영상 생성 모델은 이번 범위에 포함하지 않았다.
하이라이트 구간 선택도 기존 규칙 방식이다. LLM이 원본 전체에서 재미를 평가해
하이라이트를 다시 선택하는 구현과 구분한다.

추론은 240초 한도이며 작업 취소·새 녹음을 감지하면 네이티브 연산을 중단한다.
새 녹음이 끝나면 연출을 재시도한다. 모델·문법·메모리 오류 또는 전사문 부재 시
기본 제목·구도로 영상을 만들고 완료 안내에 기본 연출 건수를 표시한다.
이때 story.status=basic, model=none과 이유를 저장해 AI 성공으로 표시하지 않는다.

생성 결과는 분석 폴더의 *-story.json 및 MP4 옆 .json의 story 항목에 저장한다.
정상 생성된 계획은 다시 사용한다. 새 출력 키는 story8이며 이전 wide7 영상과
원본 녹음·기존 분석 체크포인트를 보존한다. 보관함 제목과 하이라이트 제목 모두
새 모델 제목을 사용한다.

3. 시동 OFF → 정상 종료: release 구현과 지원 조건

공식 API:
  android.car.Car → CarPropertyManager
  VehiclePropertyIds.IGNITION_STATE, 전역 areaId=0, ONCHANGE 구독.
  Android 14의 android.car.permission.CAR_POWERTRAIN은 normal 권한이다.
  이 권한을 manifest에 추가했다. signature 권한인 CAR_POWER는 사용하지 않는다.
  프로젝트의 Pleos Vehicle 2.3.2에 없는 PowerSystem getter를 임의로 만들지 않았다.

구현 규칙:
  - 이벤트 timestamp와 녹음 시작 시각을 elapsedRealtimeNanos 기준으로 비교.
  - 시작 이전의 캐시된 OFF, 역순/중복 값, unavailable, 연결 해제는 종료로 보지 않음.
  - 새 명시적 OFF 값만 한 번 전달. LOCK/ACC/ON/START를 OFF로 취급하지 않음.
  - 녹음 서비스가 구독하므로 화면이 닫혀도 수신 경로가 유지됨.
  - OFF → 기존 requestStop() → 세그먼트 마감·결합·M4A 검증·저널 저장.
  - 조건을 만족하는 정상 녹음이고 '녹음만 보관'이 아니면 기존 제작 작업 예약.
  - OS ACTION_SHUTDOWN은 별도로 수신하며 stopTrigger=system_shutdown으로 기록.
  - OS 종료 마감은 운영체제의 종료 제한 시간 내 최선의 처리다. 갑작스러운 전원
    차단 시 파일 저장을 보장하지 않으며 기존 세그먼트·저널 복구 경로를 유지한다.
  - 전원이 ON으로 돌아왔다고 새 녹음을 자동 시작하지 않는다.

release에는 localhost HTTP 콘솔 폴링이 없다. debug는 기존 에뮬레이터 콘솔
브리지를 유지하며 공식 구독과 중복되면 한 번만 전달한다.

실측한 현재 환경:
  Pleos Connect v2.1.0 / Android 14 API 34 / x86_64 / 약 4GB RAM.
  CAR_POWERTRAIN 권한: 실제 부여됨.
  getCarPropertyConfig(IGNITION_STATE): null, 즉 현재 이미지에서 미지원.
  따라서 공식 속성 경로의 실제 OFF → 파일 저장 시험은 건너뜀(통과로 집계하지 않음).
  대상 차량/새 이미지가 해당 속성을 제공하거나, Pleos에서 공식 전원 API를
  제공해야 실제 연동 검증을 마칠 수 있다.

주요 코드:

4. 검증 기록

단위 테스트: 70개 통과, 실패 0개.
  새 테스트: 오래된/역순/중복/미지원 OFF 차단, 모델 JSON 검증, 허구 장소 제거,
  잘못된 구도 및 대사에 없는 인물 표현 거부, 입력 길이 제한, 역할 구분자 제거,
  화자 미확정 시 전체 구도, 기존 화자·음성 데이터 유지.

기기 테스트: 실제 네이티브 모델 추론·렌더링 2개 통과.
  - SHA-256이 일치하는 모델을 별도 검증 앱에 사전 배치한 뒤 앱 코드로 읽고 추론.
  - 최종 테스트 제목: '다이어트 중인 사람의 질문'. 첫 문장 복사가 아님.
  - wide / speaker / reaction 계획 생성 후 실제 1280×720 MP4 출력 검증.
  - 전체 구도와 발화자 구도 프레임의 픽셀이 실제로 달라짐을 확인.
  - 입력 오디오 파일 SHA-256 보존, 네이티브 추론 취소 확인.
  - 최종 제목·장면 추론 50.448초, 두 기기 테스트 합계 58.830초.
  - 이전 프롬프트·동시 빌드 부하가 있던 시험은 추론 108.397초.
    두 수치는 동일 조건의 반복 벤치마크가 아니며 차량 처리 시간으로 환산하지 않는다.

시동 속성 기기 시험: 권한/지원 여부 읽기 완료, 속성 미지원으로 OFF 실동작 검증 제외.
release APK 빌드 및 Lint: 통과, 오류 0개 / 경고 88개(기존 경고 포함).
arm64-v8a와 x86_64 네이티브 라이브러리 포함, 새 라이브러리 LOAD 정렬 16KB 확인.
release APK는 프로젝트 기존 설정에 따라 미서명 산출물이며 배포·마켓 승인은 수행하지 않음.

검증 앱 ID: com.example.hd_project.verification.
기존 앱에서 녹음 중인 것을 확인했으므로 기존 앱을 교체하거나 녹음을 종료하지 않았다.
기존 앱 프로세스 PID 10444가 유지됨을 확인했다.

5. 규칙 적용 및 미검증

적용: STATE-01/04(작업 캐시·취소·세션 수명), PERF-01 및 진행 상태 안내,
API-01(실제 공개 API/권한 확인). 앱 창 dp 규격은 바꾸지 않았으며 출력 영상의
1280×720 px와 앱 창 dp를 별개로 유지한다(SIZE-01/03).
기존 CarUxRestrictions에 따른 영상 재생 제한을 유지한다(DRIVE-01/02).

사용 버전: minSdk 28, compile/target SDK 37, Pleos Vehicle 2.3.2,
SpeechToText 3.3.1, Media3 1.9.0, llama.cpp b12360, NDK 27.2.12479018,
CMake 3.22.1. llama.cpp와 Qwen3는 추가 런타임/모델이며 Android 기본 API가 아니다.

미검증:
  - 실차/ARM 기기 추론 성능·메모리와 시동 OFF 지원 여부.
  - 물리적 전원 차단, 실제 OS shutdown 제한 시간 내 저장 완료.
  - 현재 이미지가 제공하지 않는 공식 ignition 이벤트와 저장의 종단 연결.
  - 이번 변경 후 12개 앱 창 프리셋 전체 재검증.
  - 장시간 원본, 긴 전사문, 다양한 한국어 대화의 제목·연출 품질.
  - 앱에서 최초 1.3GB 다운로드부터 망 단절·이어받기까지의 전체 기기 시험.
    모델 배치·체크섬·추론은 검증했으나 전체 다운로드 시험과 구분한다.
  - 공모전 또는 Pleos App Market의 추가 모델/권한 수용 여부는 구현 성공과 별개.

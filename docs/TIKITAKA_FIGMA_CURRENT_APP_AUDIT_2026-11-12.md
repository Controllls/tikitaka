### 목소리와 캐릭터 연결

`LocalVoice`는 sherpa-onnx 2.0.1의 Android JNI와 CAM++ VoxCeleb ONNX 모델을 사용한다. 입력은 기기 내 16kHz PCM, 출력은 정규화된 512차원 특징이다. 기존 서버 모델의 192차원 암호화 등록과 모델 ID를 구분해 기존 자료를 보존한다. 확인용 녹음은 메모리에서 처리하며 새 원음 파일이나 원격 등록 요청을 만들지 않는다. 품질 검사와 두 구간의 일관성 검사를 통과한 결과만 기존 프로필에 저장한다.

제작 시 자막 구간의 목소리를 확인해 일치한 발화만 내 캐릭터에 연결한다. 긴 SDK 구간은 검사한 모든 구간이 일치해야 내 목소리로 취급한다. 미등록·불확실한 대사는 일반 캐릭터로 처리하고 같은 대사를 두 캐릭터에게 복제하지 않는다. 화자 미상의 웃음은 기존 요청대로 가능한 한 말하지 않는 캐릭터에게 배정한다. 이 웃음 배정을 실제 웃은 사람의 식별로 표시하지 않는다.

4~30초, 에너지·클리핑 검사, 등록 구간 간 cosine 0.45, 매칭 cosine 0.65는 **프로젝트의 임시 구현 기준**이다. Pleos 공식 수치나 차량 환경에서 보장된 인식률이 아니다. 이 모델은 인증·로그인에 사용하지 않는다. 동시 발화·짧은 발화·차량 소음에서는 일반 캐릭터로 남을 수 있다.

### 휴대폰 실행·데이터 범위

개발 PC: `http://127.0.0.1:8765/phone/`. 차량 앱 `설정 → 휴대폰 연결 → 연결 시작`에서 코드를 발급하고 웹에 입력한 뒤 차량에서 확인한다. 승인 전에는 영상을 읽을 수 없다. 연결 승인 시에만 기존·새 완성 영상과 자막을 동기화한다. 원본 녹음과 목소리 특징은 이 경로에 포함하지 않는다.

현재 서버는 기존처럼 loopback에 실행된다. **휴대폰에서 127.0.0.1은 해당 휴대폰 자신이므로, 이 주소를 실제 휴대폰 접속 주소로 사용할 수 없다.** 실기 연결 배포에서는 `MOMO_PHONE_PUBLIC_URL=https://접속가능한호스트`를 지정하고 HTTPS 프록시를 통해 같은 서버를 제공해야 한다. 현재 PC의 공인 네트워크 인터페이스를 자동 공개하지 않는다. 로컬 기능 구현과 외부 배포 완료를 구분한다.

휴대폰 인증 토큰은 해시만 DB에 보관하고 브라우저 쿠키는 HttpOnly·SameSite=Strict, production은 Secure를 사용한다. 차량 승인 전 5분, 승인 후 30일 만료이며 연결 해제 즉시 접근을 막는다. 설치 사용자별 파일 접근과 변경 요청의 Origin·전용 헤더를 검사한다. 운영 DB 마이그레이션은 `0004_phone_companion`이다.

완성 영상 사본은 서버의 `storage_root/phone/`에 보관한다. 공유 미리보기에서는 자막을 포함한 별도 공유용 사본을 만들고 오디오 스트림을 복사한다. 실제 외부 공유는 사용자가 공유 버튼과 OS 대상을 선택한 경우에만 진행한다. 파일 공유 API가 없는 브라우저는 명시적인 다운로드를 제공한다. 휴대폰 개별 삭제는 원본 서버 사본·공유 사본·자막·포스터를 제거하며 차량 파일은 유지한다. 설정의 연결 해제는 접근 권한 해제이며 사본 일괄 삭제가 아니다.

## 후속 개발: 다중 캐릭터와 웹·Figma 비교

**현재 앱이 웹과 Figma의 모든 기능을 구현한 상태는 아니다.** 아래 절은 후속 수정 결과이고, 이후 기존 95항목/32건 검토 본문은 수정 전 이력으로 보존한다. 이전 문서의 한 명 고정·40초 고정·상세 제작 버튼 없음 설명을 현재 구현으로 읽지 않는다.

### 한 명 생성 원인과 수정

`TikiScene.buildPerformance`가 사람 목록을 한 명으로 만들고 `MetadataEpisodes.bundle`이 대사·웃음을 같은 `performance` 트랙에 몰았다. 현재 경로에는 실제 화자 식별이 없으므로 분리 결과를 잘못 읽은 문제가 아니라 한 명으로 축소해 작성된 제작 로직의 문제였다.

기본 두 명, 설정에 따라 1~4명을 배치한다. 내 캐릭터는 대사를 연기하고, 발화자 미상의 웃음은 가능한 한 말하지 않는 동행에게 배정한다. 같은 대사를 복수 캐릭터의 자막/입 움직임으로 복제하지 않는다. 프로필은 제작 시작에 보관한 암호화 스냅샷을 사용하고 실제 이름을 표시한다. 이 연출을 실제 화자 구분 또는 내 목소리 인증이라고 표시하지 않는다. 같은 녹음의 재시도·새 버전은 최초 프로필을 유지하며 이후 새 녹음에는 변경 프로필을 적용한다.

## 1. 검토 결과와 읽는 방법

검토 파일의 본문·표를 원문 순서대로 95개 항목(P001~P095)으로 나누어 모두 대조했다. 별도로 보관된 Figma 기능명세 FN-01~20을 확인했다. 중복을 합친 차이·개선 항목은 32건으로, 문서 현행화 10건(D01~D10)과 구현·품질·디자인·정책 확인 22건(B01~B22)이다. 모두 같은 심각도의 버그라는 뜻은 아니다.

가장 먼저 볼 항목은 B01(제작 중 캐릭터 고정 실패), B03(긴 녹음의 지수 대기), B04(STT 시간 초과·자막 잘림), B06~B08(실패 녹음의 복구·목록·결과 분기)다. 이름 적용 B02, 원음 상세 제작 B11, 에피소드 표시 B12와 기준 화면 배치 B15도 현재 동작과 명세가 다르다.

원 검토 파일은 초기 적용 기록으로서 의미가 있다. 당시 테스트 수치가 현재와 다르다는 이유로 과거 결과를 허위라고 판정하지 않았다. 이후 화자 기능 축소와 기기 분석 전환 때문에 달라진 내용은 문서 수정 대상으로 분리했다. 위치·날씨 제거 요청, 휴대폰 미구현의 기존 고지, 일괄 삭제 보류도 새로운 구현 결함으로 세지 않았다.
